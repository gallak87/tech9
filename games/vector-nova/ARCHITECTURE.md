# VECTOR//NOVA architecture

## Stack and module boundaries

Standalone Vite + Three.js ES modules, WebGL2, PBR/ACES and sRGB output. No repository framework, alternate launcher or cloned runtime. See the [README](README.md) for available circuits and the [roadmap](ROADMAP.md) for planned work.

The locally owned ESLint/Prettier/lint-staged/Husky configuration was adapted from Chronoforge Echo at the user's request.

| Module                 | Responsibility                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| levels                 | Validated discovery, per-level factories, metadata and presentation adapters              |
| core                   | Boot/readiness, fixed-step session, replay, mode changes and teardown                     |
| track                  | Optional route-frame, sweep and geometry mechanics                                        |
| environment / renderer | Optional placement mechanics; shared rendering, lighting and resource metrics             |
| ships / camera         | Selectable async fleet assets and local presentation; road-frame chase/inspection cameras |
| physics / race         | Vehicle motion and rail response; checkpoint/lap validation                               |
| input / ui             | Normalized controls, focus/visibility cleanup, menus/HUD/settings                         |
| audio / effects        | Event-driven presentation; failure must not stop simulation                               |
| pickups                | Shared automatic devices and owned visual/audio presentation                              |

`src/levels/<slug>/track/`, `environment/` and `backdrop/` own each circuit’s route, construction, materials, scenery and sky; Nacre also owns its overlay and flight presentation adapter. Shared directories contain reusable mechanics, never a default world style. Asset URLs follow stable level/ship folders; replay identities are independent of asset filenames.

`src/levels/` discovers asset-free metadata eagerly and imports only the selected implementation. Its [level API](docs/LEVEL_API.md) defines factories, presentation and ownership; unknown or malformed levels fail visibly.

## Front end and world ownership

`src/core/main.js` starts the asset-light `src/frontend/` shell directly on the scrolling circuit card library. At widths of 1200px and above, circuit cards, race mode/difficulty, the ship studio and vertical performance stats share one setup screen with a single Start action. Narrower screens reuse those controls in stacked Circuit/session and Ship accordion sections; mode selection advances to Ship, and either header reopens its section. Start stays above the accordions beside Resume when a session is on hold, so ship stats never push the action below the fold. Resizing preserves selections and focus. Start → Loading → Race → Results is the normal flow. Only Start constructs a world. Hover and arrow-key focus preview circuits/ships without changing the selected session; click or Enter commits, and leaving the list restores the selection. Circuit previews read cached stills; ship previews reuse the studio renderer and parsed model cache. Quick Race uses the existing two-lap competition; Practice is open solo driving. Ship selection displays the actual GLB in a fixed-size, drag/keyboard-controlled studio that draws only on model/view/size changes and releases its WebGL context on exit. CSS size containment keeps canvas resolution independent of layout. Settings includes the keyboard legend; lists use arrow/Home/End navigation and roving focus, alongside native Tab/Enter/Space controls. Explicit `?level=` links select a circuit without loading it; `?review=`, `?test=` and `?capture=1` retain the clearly labelled developer launcher for tools. These routes preserve the title/pause controls and DOM selectors used by the level contract. `?inspect=1&ship=kestrel&level=halcyon` loads the selected world directly into the existing ship inspector, with Tunes disabled; Back returns to setup and clears developer flags. Art-pass takes precedence over inspector/test flags. In-session I still returns to the same session. Consolidation of the compatibility launcher and historical harnesses remains on the roadmap. `window.__VN` remains the current runtime API; `window.__VN_FRONTEND.getState()` reports shell and preload state.

`src/ships/model-cache.js` preloads Kestrel first, then the remaining player GLBs in the background. KTX2 capability detection reuses a live studio/race renderer when available; otherwise a temporary unattached 1px WebGL renderer detects support and immediately releases its context. This allows all four compressed models to preload while the narrow Ship accordion is closed, without constructing a level or running a hidden studio. Concurrent demand loads share a promise; failed requests remain retryable. Parsed sources live for the page session, across world disposal. Each `createShip` clones source geometry/materials/textures into independently disposable presentation resources; cached sources never borrow a renderer or own uploaded scene resources. Page teardown releases the cache after worlds/previews. A shared status strip sits directly below the ship studio for fleet transfer/parse progress, and below the circuit hero during world construction. The collapsed Ship accordion row also shows preload status before that section opens. It is absent from driving and settings.

`src/core/game.js` exports `createGame({host, parameters, signal, onProgress, onMode, onHome, onResults, onCircuit})`. The shell serializes cancellation, disposal and world creation. Phase checkpoints yield between route/graphics/world/ship/warmup tasks and surface errors with retry/back. Individual synchronous constructors and first GPU submissions can still stall; this is not a complete M1 performance pass. One loaded world and one active session are retained: Escape pauses, Circuits suspends rendering/input, and Resume restores the same run or results. Browsing cards/ships does not mutate it. Only explicit Start calls `prepareSession()` before configuring a new chassis/run; starting a different circuit disposes the old world and WebGL context. All loading exits cancel through the same path. In-race inspection preserves its return mode and locks chassis changes. `src/progression/` owns one live settings snapshot; shell and runtime subscribe, including pause controls, and storage failure never breaks in-session synchronization.

Tunes belongs to the shell, outside world disposal, with one native audio element and a fixed top-right anchor. Track, position, queue and volume persist through loading and gameplay. At widths up to 760px, a logo-aligned Tunes button opens the full controls below, including during driving; wider screens retain expansion in menus/pause. Music ships as committed 192 kbps stereo MP3s; WAV masters stay outside `public/`, with local encoding documented in the [audio guide](docs/audio/README.md#encode-for-web-delivery). Current audio uses automatic preload and stable asset URLs; initial construction buffers without playing. Start race/practice starts music if it is paused and the user has not manually paused it; ordinary menu buttons and race restarts never start playback. Explicit Play/M controls playback at any time, and already-playing music continues through launch without restarting. Next-song switching and controls still need JavaScript; continuity under severe resource pressure requires separate performance testing.

### Circuit preview refresh

Circuit thumbnails are saved **640×400 WebP captures of the real pulled-back free camera at Low quality**. They are runtime assets, not live views or verification evidence. The capture hides racers/effects, backs away from the grid, lifts the camera and aims toward the route centre. Hover only switches the saved image. `tools/menu-catalog.mjs` generates SVG outlines/facts from CPU route models; it never imports world factories or recursively scans/hashes source or asset trees.

Saved images remain visible across source changes. A genuinely missing file falls back to the route outline with a developer warning; malformed WebPs, incorrect dimensions or invalid manifest paths fail the build. Route-signature/preset differences are **advisory** warnings, never visibility gates. They cannot detect scenery, lighting or borrowed-asset changes: explicit refresh remains the author’s responsibility.

After final visual changes, from this app directory:

1. Use Node 22 and an existing dev server, or start one on a free port: `npm run dev -- --port 5197`. Preserve servers owned by other sessions.
2. Refresh named circuits explicitly: `VN_URL=http://127.0.0.1:5197 npm run previews -- halcyon nacre`. Named circuits are always recaptured. No IDs refreshes all circuits; `--missing` only fills missing stills. The old `--force` spelling remains accepted.
3. Refresh consumers of borrowed/shared art too, including wide variants. Shared visual changes need an all-circuit refresh. Unrelated code or formatting changes do not require recapture.
4. Inspect the changed images, build, and commit each WebP with `public/assets/menu/previews.json`. Close your own server/browser. Do not keep parallel captures, reports or audit JSON.

The version-1 manifest records each filename, dimensions, capture preset, source revision/dirty flag and CPU route signature. Migrated images retain their old fingerprint as provenance with `sourceRevision: null` because the original exact revision was not recorded; no new capture is implied. The tool updates each record immediately after its image is saved. Source revision is provenance, not an automatic freshness test. Capture uses `?level=<id>&capture=1&music=0`; the compatibility launcher is intentional here. The shipped stills and user-requested art concepts remain registered in [the asset manifest](docs/ASSET_MANIFEST.json).

## Route, coordinates and handling

`src/input/touch.js` supplies two independently captured pointer controls to the shared input sampler: left/right analog steering with a downward airbrake zone, and a right-hand Boost/Go/Neutral/Brake rail. Boost also holds throttle. Each pad retains one pointer through out-of-bounds drags; release/cancel/lost capture resets only that pad. Input clear, pause, suspension, focus loss and viewport resize reset both pads and their indicators. Touch feeds the existing normalized input and physics; keyboard and gamepad mappings remain unchanged. Narrow, short-landscape and coarse-pointer viewports expose the pads, with telemetry kept clear of them.

- Metres/seconds/radians. World +Y up; ship local +Z forward, +Y up.
- `sample(distance)` wraps arc-length metres and returns `{position, tangent, right, up, quaternion, curvature, bank}`, optionally `roll`. Road, ship, camera and physics consume the same frame.
- The legacy `frame.right` is geometric +X, which appears driver-left when facing +Z. Positive input steer means driver-right: negative geometric heading/lateral displacement. Do not reverse this when adding levels.
- Reuse `src/track/frames.js` for continuous parallel-transport frames through vertical tangents/inversions and lap closure. Reconstructing every frame from world-up crossed with tangent fails at vertical directions. The optional [geometry helpers](src/track/README.md) retain authored profiles and local clearance rules; no shared world preset is applied.
- Track models expose unique/versioned identity, length, full width, ordered checkpoints, contiguous named sections, scenarios and bounds. Production and shape views share one route.
- Fixed simulation is 120 Hz, capped at 0.1 s / 12 catch-up steps. Pause/visibility loss clears the accumulator. Render interpolates distance and quaternion; presentation never mutates simulation.
- Bend assistance is 0.3. Persistent heading retains the unassisted yaw, while a separate steering response preserves manual turn-in. Pitch/roll adhere to the magnetic surface.
- Gravity projects through tangent/right axes; explicit parking hold prevents slope/bank creep. Yaw-aware swept rail bounds resolve collision, reserve loss and lateral response. Manual recovery clears heading and invalidates the lap.

Shatterline retains stable authored source addresses while its physical road folds back beneath earlier reaches. `distanceAt`/`sourceAt` convert source addresses and race arc length; `pointAtSource` returns actual world position. `spineZAt`/`sourceAtSpineZ` describe only the monotone scenery reference spine. Their compatibility aliases `worldZAt`/`sourceAtWorldZ` are not inverses of physical road Z. Placement near crossings must use actual three-dimensional road positions and branch clearance, with `nearestSourceAt` available for spatial ownership.

Shatterline opts into a course-owned pace profile shared by grounded motion and rival speed selection. Per-ship cruise and boost targets scale independently; lower excess-speed resistance carries earned descent and landing momentum while throttle-off drag and ordinary brakes remain effective. The profile joins runtime identity. Omitted or neutral profiles preserve the approved physics arithmetic of existing courses.

Overturn weaves through two transparent, freely drivable 70 m tubes with opposing physical bends, separated by a steeper exposed corkscrew. `track.tubes` describes each opening and closed span, `tubeAt`/`tubeProfile` select by distance, and one `tubeMesh` supplies exact shared facets for rendering, collision and hull support. The level-local surface sampler covers the entire district, including its exposed rolls, while neighboring jumps keep their world positions. Shared physics integrates surface metrics and tangent-plane gravity; periodic lateral coordinates cover each complete interior. Camera, grounded poses and contact effects use the same sampled surface. Red exit inlays begin 100 m before each opening and converge through its collector onto the road. Inside those red intervals only, a real rim hit gives a forgiving inward impulse and brief gradual heading recovery toward the outlet, with reduced speed/reserve loss. Clean lines, closed-tube wall rides and ordinary roads retain their handling.

Halcyon uses a 5 km route with distributed rise/descent, full roll/inverted hold and plunge. Asterion uses 4.5 km with a wall ride, raised crossing and steep dive. Authored dimensions and section data belong in their models, not duplicated documentation tables.

## Session, devices and replay

`src/core/session-runtime.js` provides the ordinary magnetic adapter and one `advanceSession` path shared by live input and replay. The [session adapter contract](docs/LEVEL_API.md#session-adapters-and-replay) defines hooks and event order. Preserve identity `{id, version, rulesId}`; replay also checks app/track/physics versions, seed and deterministic initial state. Reject incompatible or incomplete logs.

Production descriptors declare `racing: { createDevices, createMotion? }`. Core wraps the player's existing motion adapter with `src/pickups/runtime.js`, and creates each opponent with that circuit's pure motion factory and the same device layout. `src/race/racers.js` supplies three independent vehicle/race/device states and deterministic steering, braking, manual boost and lane decisions. Rivals borrow the fleet's versioned handling profiles (Rook/Kestrel, Latch/Shrike, Mule/Bastion) while rendering their own GLBs. All four clocks start together on a 2×2 grid; rear-row travel to the start counts toward time without crediting a partial lap. Easy leaves more cornering margin and conserves reserve; Medium carries more speed and boosts more often; Hard targets a close race against clean, boosted driving. Every difficulty receives the player's full Vector propulsion and preserves earned speed instead of braking back to its preferred cruise pace. Braking handles corners, traffic and required-jump launch speeds. Manual boost uses each rival's own reserve independently of player inputs; difficulty never changes vehicle or device physics. Difficulty is fixed for the run. The pause menu can save a new difficulty for Restart Race/Restart Sprint; Resume keeps the current run unchanged. Solo practice and verification scenarios disable opponents and hide the pause difficulty picker.

Halcyon, Orbital, Nacre, Vesper, Glasswake, Cindercoil, Saffron, Umbra and Helion use this shared system. Nacre retains its approved version-5 landing solver inside the shared device wrapper. New circuits must declare the shared racing capability rather than implement independent devices, AI, countdown, HUD or results. Opponents render their actual interpolated flight pose and use their own reserve to reach required-jump launch speed; optional branches remain route choices. CPU adapters never own the player's local presentation ledger.

Human launches use the shared HTML/CSS start lights and three countdown beeps followed by a longer kickoff tone. `src/core/start-countdown.js` uses a pausable wall clock, armed after audio unlock settles and the first driving frame renders. Late frames cannot skip lights; each newly presented beat gets a full second. Vehicles, lap clocks and replay recording remain frozen until lights out. Held throttle and Shift survive the countdown-to-green transition; boost engages when the existing speed/reserve requirements are met. Input still clears on pause, suspension and focus loss. The internal verification restart/scenario API bypasses the countdown. Audio unlock failure cannot prevent launch.

Competitive runs latch each racer's first two checkpoint-complete laps and classify valid finishes by total time; invalid runs remain explicitly unranked. Practice never acquires a competitive finish flag. Three red start lights turn green on GO. `src/race/finish-marker.js` places a small shared checker mesh at checkpoint zero (or an open route's `finishDistance`), conforming to road banking; optional `racing.finishMarker` paint dimensions/tones remain level-local. Completion events pass through the shared tick's event stream to a distinct finish cue and headline. A 2.4-second track-visible finish beat brakes the player and gently widens grounded chase (no camera move in reduced motion), then fades in a compact track-backed results panel. Rivals retain independent clocks until they actually finish. Continue Driving preserves the recorded result; Pause can reopen Results, and recovery does not reopen it automatically. Audio keeps finish tails audible while stopping propulsion/environment in results. Replay records competitive/solo mode and difficulty and advances rivals through the same fixed ticks; rejected initialization restores the prior field and presentation flags.

The driving HUD shows position, lap count, personal current/last/best lap times and all four racers in race order. Mid-screen gameplay callouts and the section-name readout have been removed across all circuits: do not add jump approach, landing/recovery, surface/hazard commentary or lap-result toast components. Countdown/results, device/heat gauges and non-text environmental effects remain. Relative gaps use YOU as 0.0s, negative for rivals ahead and positive for rivals behind. `src/race/relative-timing.js` retains bounded passage samples on unwrapped course distance, interpolating the leader's passage at the trailing ship's current point; gaps never subtract lap clocks or divide distance by current speed. Recovery/reversal clears that ship's passage history, unavailable gaps remain unknown, and replay rollback includes the samples. Recorded lap/total finish times appear in the paddock. Rival minimap dots and row strips share one stable color per identity; the player has an orange marker with a white outline.

Open courses opt in with `track.closed === false`; `finishDistance` is the final checkpoint and `length` includes safe runout. The race latches one grounded ordered finish, then supplies ordinary braking controls while each unfinished rival continues independently. Sprint HUD, open minimap markers and solo results reuse shared UI. Airborne presentation progress follows the real pose within its jump corridor and never grants checkpoints. Sprint identities include format, finish and geometry; field rollback retains validated transfer keys. See the [level API](docs/LEVEL_API.md#track-and-review-contract).

Vector strips apply a +65 m/s entry impulse at leading hull contact, capped at their 600 km/h target, and add strong propulsion only while the hull overlaps the strip. The per-call road profile can exceed the selected ship's manual boost; holding boost selects the stronger active profile and still spends reserve. Exiting removes the force immediately and retains actual vehicle speed; no timed boost or reserve charge remains. Sweeps include yaw, lateral entry and lap seams. Device ticks expire Aegis's six-second protection and apply brake cancellation before physics, consume shields on qualifying impacts, then sweep new contacts. A shield collected later in a tick cannot protect an earlier impact. Effects do not stack; manual recovery clears effects while retaining the consumed-device ledger. Reverse/parking/reset farming must not rearm devices. Shields protect reserve loss, not collision separation or speed consequences. Shared rules, geometry, presentation and audio live in `src/pickups/`; placement plans live in each circuit's `devices.js`. Vector chevrons are pixel-filtered paint on the opaque casing, avoiding subpixel sliver geometry without extra textures or draws. Every road declares its rendered running skins with `mesh.userData.roadSurface` and metre-based `roadCoord` attributes. Shared pickup presentation measures those triangles to seat casings above the panel envelope; levels supply geometry only, with no mounting callbacks or per-level offsets. Missing surface declarations fail loading instead of silently falling back. Ground devices do not trigger in flight/recovery. The motion adapter receives per-tick propulsion/shield modifiers; Aegis protects rail-edge reserve loss without changing airborne deflection or landing geometry.

The opt-in `src/physics/flight.js` model supplies ballistic flight, swept landings and timed recovery. Nacre's adapter retains its authored rules, identity, scenarios. Level adapters may supply pure grounded surface/force and airborne force samplers; zones, heat and events remain level-owned. Per-call surface options default to unchanged magnetic response. Optional authored jumps retain supported main-road traversal; actual transfers keep strict landing-checkpoint validation. See the [level API](docs/LEVEL_API.md#shared-local-mechanics). Automatic missed-jump recovery counts its delay as elapsed time and retains a valid lap; manual recovery still invalidates it. Keep Nacre-specific tuning out of the ordinary magnetic adapter. Local flight, surface, hazard and force rules use versioned session adapters. Shared defaults remain compatible with existing circuits.

Levels can opt into `createCollisionWorld({ track })`. Core owns one CPU world before presentation and shares it with the player and independent rival runtimes. `src/physics/collision-world.js` indexes authored triangles in a BVH and sweeps the whole oriented arcade hull with continuous translation and conservatively bounded rotation. `src/physics/hull.js` centralizes its established dimensions/projection math. Physical detection precedes landing acceptance: heading, half-width support and the current jump interval determine relatching only. Rejected borders deflect along their actual normal; solid deck/scenery hits bump into timed recovery. Recovery keeps sweeping, with six contacts per substep and deterministic impact cooldown/state. Geometry and collision rules join replay identity; world contact positions/normals reach shared sparks and Aegis feedback. Levels without a collision world retain their existing path. The eight expansion flight circuits register exact production road solids around their jumps with level-owned selection; Vesper also bakes its placed landing bough from the production GLB. The shared extractor preserves gaps and instance transforms without depending on presentation quality. Cindercoil also registers its production deck, ramp-end faces, walls, keel and large supports in a bounded vent-jump corridor; distant scenery and the environment GLB remain outside that first pass. Racer body contact remains deferred.

Descriptors may also opt into async `createDynamics({ track, collisionWorld })`. Core owns one shared `src/physics/rapier-world.js` service and passes it to every motion adapter. Saffron uses pinned Rapier 0.21.0 for airborne and falling-recovery translation, rotation, friction and CCD against the same authored static triangles; grounded magnetic handling and 0.3 assistance stay unchanged. Session stages player/device/rival hooks, steps the engine once per 120 Hz tick, then resolves ordered events and race timing. Collision filters exclude racer body contact. Runtime identity includes engine/geometry/solver rules; replay initial state and failed-playback rollback retain one complete session engine snapshot. Full resets rebuild the world before actor resets, while manual recovery resets only the player actor.

## Ship and rendering

`await createShip({id, ...options})` returns `{group, update, dispose}`. `src/ships/catalog.js` owns asset-free ship identities, handling versions and tuning. `createFleetShip` retains a stable root for borrowed level effects while replacing and disposing the selected chassis; failed loads retain the current model. Core restricts switching to menus, blocks launch during loading, refreshes camera bounds and starts a fresh deterministic state. Selection persists when local storage is available. Vehicle state carries `shipId`; grounded physics reads its profile while steering assistance stays 0.3. Replays check ship id/version and lap rules are ship-scoped. Load the GLB before measuring inspection bounds, baking reflections or warming shaders. Core owns world pose; update animates only local presentation. Editable sources, concepts and provenance live in `assets/ships/<id>/`; runtime GLBs live in `public/assets/ships/<id>/`. Kestrel keeps its dedicated exporter; `assets/ships/build_fleet.py` builds the three additions. Both share `assets/ships/surface_finish.py` for original PBR and cavity-occlusion bakes. See [ship API](src/ships/README.md).

High uses single-sample HDR with sampled depth, localized exhaust refraction, GTAO, restrained bloom, OutputPass and SMAA. The renderer owns the half-resolution exhaust displacement field and its composite; it borrows visible plume transforms/pressure during each frame. Hull-space bounds plus scene depth guard foreground and craft pixels. Low, shape review and reduced motion disable the distortion. The plume uses simulation-time pressure/flow and is excluded from AO geometry. The shared radial world blur becomes strong on Vector contact, with a fast attack and clear vanishing point/craft center. High retains a subtler speed/manual-boost blur after launch; Low runs the composer during catapult contact or while a level-owned world pass is enabled; otherwise it renders directly. Nightweir water and Worldspire clouds retain their linear composition on both quality presets. Blur is disabled outside racing and with reduced motion. Multisampled HDR plus GTAO caused an ANGLE Metal opaque-region fault; retain the working pipeline. DPR caps are 1.25 desktop / 1 mobile.

Sky PMREM and a static scene probe approximate reflections; these are not realtime reflections. Renderer-owned reflection textures are borrowed by ship/environment materials and must not be disposed by borrowers. Road coverage masks the analytic contact footprint over real apertures.

Camera damping follows transport through the road frame, with quaternion rotation and local road clearance to handle inverted decks and steep crests. Inspection fits the loaded ship's bounds to the available UI region. Pooled road lights use continuous fades; thin road details must follow the tessellated surface to avoid flicker.

| Level concepts, editable Blender sources/generators, source textures and provenance | `assets/levels/<slug>/`, using `reference/`, `blender/` and `textures/` as useful |
| Level runtime models and textures                                                   | `public/assets/levels/<slug>/`                                                    |

| Runtime geometry/materials, placement and loading                                   | `src/levels/<slug>/` or `src/ships/`                                              |

Keep the `rivals/` subdivision: it distinguishes AI chassis from player-selectable ships. Keep exact image prompts, selected references, licences and all inputs required by current generators with their sources. Embedded GLB textures do not need separate runtime PNG copies. The [asset index](docs/ASSET_MANIFEST.json) points to detailed provenance rather than duplicating review history.

Vite copies the whole public directory into each production build, including unreferenced exports. Retire obsolete runtime versions after checking consumers and generator dependencies; temporary renders belong in ignored `.experiments/`. Current level runtime assets all live under `public/assets/levels/<slug>/`. Nacre editable studies live under `assets/levels/nacre/blender/`; Orbital texture generation/provenance lives under `assets/levels/orbital/`. Earlier authoring exporters write unserved GLBs into ignored `.experiments/`, while their Blender inputs remain available for current generators. Rival generators write one canonical public GLB, validated against its manifest hash. Update loaders, generators, provenance and asset checks together when moving them; keep track/rules/replay identities independent of folder names.

Level discovery imports only the selected implementation. Fleet selection loads the selected player GLB; competitive circuit boot also loads its three rival chassis, and rival inspection owns a separate loaded instance. All runtime loaders use `src/assets/url.js` and respect Vite's base URL. Preserve ownership and readiness when normalizing paths.

## Lifecycle and verification

One owner releases each geometry, material, texture, listener, audio node and animation callback. `createLifetime` unwinds owners in reverse order on shutdown or failed boot; inspection owns only its floor/ring, and level components borrow renderer probes/sky textures. The shared presentation controller updates road, environment and backdrop once per frame, supplies zero dt outside racing and propagates resets. Camera flight/portrait behavior uses explicit descriptor options. Await owned assets and shader warmup before setting ready. Warmup compiles direct and HDR scene variants, renders deferred level passes and the zero-strength speed blur, then synchronizes the first GPU submission before readiness. Dispose must be idempotent; failed boot should show a useful reload error. Audio/storage failure stays recoverable, and context loss pauses.

Every circuit includes the shared free inspection camera: F or the paddock/pause Free Camera button enters from the current camera pose; drag-look, WASD/arrows and Q/E move through the full environment at a fixed 200 m/s. The `fly` mode freezes simulation, lap timing and replay recording, and hides the player, rivals, contact shadow and impact particles. Returning restores the prior racing/paused/title/overview/countdown mode and clears controls. Its keyboard/pointer/touch listeners are owned by `src/core/fly-camera.js` and disposed with the session.

For agent/art inspection, `?artPass=1&level=vesper` bypasses setup, loads the production environment and enters free camera with Dev tools open. Tunes is never created in this page session, even with `music=1`; saved music preferences are untouched. Optional `&cam=100,200,-300&look=0,40,100&fov=55` sets world-space position, look-at target and vertical field of view. Supply both coordinate triples; FOV alone is also allowed (10–120 degrees). Invalid views show a loading error. Art pass takes precedence over `review`, `test`, `case` and `capture`; those entry paths behave normally without `artPass=1`. Leaving special entry for circuit selection clears these launch/view flags.

Dev tools' **Copy view link** captures the current camera pose and level in an art-pass URL; clipboard denial exposes a selectable URL instead. Agents can read the same link with `window.__VN.getArtPassURL()` or jump live with `window.__VN.setFlyView({ position: [x, y, z], target: [x, y, z], fov: 64 })`. The latter enters free camera and synchronizes mouse-look orientation; `openDevTools()` opens its panel. Movement keys remain active with the panel open/focused. Links reproduce camera framing, not saved graphics preferences, animation time or race state; keep quality and viewport consistent when comparing performance or images.

Free camera's **Dev tools** button or P opens live graphics controls without moving the camera or advancing the session. Escape closes the panel before leaving free camera. FPS and average frame interval update every half second from rendered animation frames; draw-call/triangle counts include all renderer passes and are not unique scene totals or GPU timings. Circuit-specific art-tuning controls belong only in the free-camera Dev tools panel, including art-pass entry; keep them out of the main Settings and pause menus. Vesper adds independent persisted switches for clearcoat, internal resin layers and procedural organic surface detail. All default to the authored appearance; Restore material defaults affects only those switches. Shader-changing toggles may briefly compile a new variant. Vesper resin is permanently opaque; reflections and internal inclusions provide depth without a scene transmission pass. Glasswake’s crystal road uses alpha transparency, reflections and textured relief without physical transmission or an extra scene-refraction pass; High and Low retain their separate shading presets.

Halcyon owns a metre-scaled asphalt material in `src/levels/halcyon/track/asphalt.js`. The CC0 Poly Haven Asphalt 03 scan repeats every 2.05 m in both road directions: 2K color/OpenGL normal plus 1K packed AO/roughness, with mipmapped UASTC KTX2 and bounded anisotropy. Separate road-space moisture modulates roughness and darkening across several metres, without stretching the aggregate or adding geometry/passes. `assets/levels/halcyon/asphalt/build.py --toktx <path>` rebuilds runtime maps from retained sources; provenance records source and runtime hashes. Boot awaits all maps; the road owns/disposes its textures and material, while the existing ship transcoder files are shared.

Asphalt is the sole Halcyon running surface. The Dev tools panel exposes **Road sheen** and **Nearby reflections**; **Reset asphalt finish** restores 80% sheen with the existing district probe. The three compressed maps occupy about 12 MiB on ASTC/BC7 hardware, with no extra draw calls. The borrowed probe is a static local approximation, not live reflections along the whole route.

# Level module API

The shared app discovers circuits under `src/levels/<slug>/`. This document defines the shipped metadata, factories, ownership and runtime options. Session adapters follow the [contract below](#session-adapters-and-replay).

## Discovery and metadata

Each level supplies two files:

- `metadata.js`: default-export an asset-free object with `id` matching the folder, `name`, numeric `order`, boolean `shape`/`review`, and `ui` copy. Metadata feeds the paddock picker, briefing and review controls.
- `index.js`: default-export `createLevel({ shape })`, returning the descriptor below. Only the selected implementation is imported. No shared catalog/core edit is required.

Required `ui` strings: `edition`, `subtitle`, `intro`, `tag`, `tagDetail`. The paddock title comes from `name`, with its first word large and the remainder as a smaller italic subtitle; a single-word name uses the circuit part of `ui.subtitle`. Legacy `heading`, `eyebrow`, `detail` and `start` are accepted but no longer used by the paddock. Optional `ui.shape` overrides copy for shape review. Optional layout flags are `compact`, `stackedReview`, `lowNotice`, `compactLandscape` and `portraitCompactHud`. Use real text, not HTML. The approved level metadata files are small working examples.

Every level includes shared environment inspection without a metadata flag: F enters, drag looks, WASD and Q/E move at a fixed 200 m/s, and F/Escape/Return restores the previous view. Session time, vehicle and replay recording are frozen. The controller owns its listeners; no level-specific camera fork is needed.

Complete working examples are the [Halcyon descriptor](../src/levels/halcyon/index.js), [Orbital production/shape descriptor](../src/levels/orbital/index.js) and [Nacre custom-runtime descriptor](../src/levels/nacre/index.js). Reuse their factory/ownership pattern, while authoring your own route, assets and presentation.

Unknown slugs, orphaned modules, invalid metadata and missing required factories produce a recoverable error screen. Query text never becomes an arbitrary import path. The default route remains Halcyon; production uses `?level=<slug>` and shape adds `&review=shape` when supported.

## Descriptor and owned components

The optional `audio` descriptor configures the shared audio owner. `audio.environment(context, bus)` may return a level-owned `{ trigger(event), stop(), dispose(), getPresentation?() }` voice component. The context is the existing, gesture-unlocked AudioContext and `bus` feeds the shared compressor/master gain. `trigger` receives session events only while running and audible; `stop` runs on pause, mute or environment reset, and `dispose` releases owned nodes before context closure. Reject unrelated event types locally. Keep sound synthesis and tuning in the selected level.

Required descriptor fields:

| Field                          | Result                                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `version`                      | Stable replay/app version string; change when compatibility changes.                                    |
| `createTrack()`                | Track model, or a promise for it.                                                                       |
| `createRoad(context)`          | Owned road component; select neutral shape or production geometry using the factory's `shape` argument. |
| `createEnvironment(context)`   | Owned world component, including scenery and local effects.                                             |
| `createBackdrop({ settings })` | Owned backdrop; see rendering below.                                                                    |

Road/environment context is `{ track, collisionWorld, view, host, settings }` (`collisionWorld` is null when omitted). Environment factories additionally receive `road`, the acquired, ready road component. They may call local attachment methods on it; ownership and disposal remain with the presentation loader. Each component returns `{ group, dispose, ready?, update?, reset?, setReflection? }`. `group` is a Three.js Object3D. Core attaches/removes it; the component releases its own resources. Factories may be async; `ready` may await further owned assets. Boot awaits all of these and shader warmup before marking the app ready. A rejected load unwinds acquired owners.

Each component's `update(frame)` runs once per displayed frame. The frame contains `{ state, ship, camera, settings, time, dt, mode, reviewing, reset, motion }`; `state` is interpolated, `time` is simulation time, and `dt` is zero outside racing. Treat inputs as read-only. `reset` is true on initialization, scenario/replay changes, recovery and fresh sessions; use it to clear presentation history. Inspection/pause must not advance racing effects. `setReflection(texture)` borrows a renderer-owned texture: never dispose it.

A level overlay may call `view.attachWorldPass(pass)` to insert a borrowed postprocessing pass before tone mapping. The returned function detaches it; the level must detach and dispose its own pass. `pass.enabled` controls activation in both quality presets. Composer resize reaches attached passes, and shader warmup temporarily enables them, so supply inert initial uniforms. World passes process the rendered scene and ship without distorting the HTML HUD. Umbra uses this for a bounded, force-directed lens beside the hull; reduced motion preserves a static rim and HUD arc while disabling image distortion, smear and flow.

Optional descriptor fields: `createRuntime(context)` replaces only the session adapter; otherwise ordinary magnetic motion is used. `createOverlay(context)` returns `{ dispose, update?, afterRender?, reset?, getPresentation? }`. `ship`, `audio` and `effects` pass existing constructor options; `railContactSparks` chooses rail-local spark placement and `practiceSectionsUntimed` labels section practice. `audio.immersion({ camera, track, state })` may return a 0–1 submerged listener blend; core and shared device cues use the same smooth output filter/gain response. `frame.motion` contains the current adapter snapshot for presentation-only flight/contact observations. These are extension points for declared level-specific rules. Versioned adapters support true jumps, surface response, hazards/heat and environmental forces while preserving defaults for other circuits. Production circuits also declare the shared racing capability below.

Optional `createCollisionWorld({ track })` returns a CPU-only `{ id, version, rulesId, sweepHull, dispose }`, synchronously or asynchronously. Core validates and owns it once per selected level, before presentation, and passes the same `collisionWorld` to road/environment, the player runtime and each `racing.createMotion` factory. It must not depend on meshes, quality, DOM, frame callbacks or mutable racer state. Derive colliders from shared authored geometry/samplers; the level owns coverage and geometry revisions. Omission preserves existing physics.

`src/physics/collision-world.js` builds this service from `{ id, version, geometryId, triangles }`. Triangles supply three world-space `points` and stable `{ id, kind }` metadata; `kind` is `deck`, `rail`, `terrain` or `structure`. Road pieces also supply route `start/end` or a fixture `distance` for landing classification. `sweepHull(beforePose, afterPose, hull)` returns the earliest `{ fraction, position, quaternion, point, normal, surfaceNormal, penetration, shape }`, or null. `position/quaternion` describe the swept hull; `point/normal` describe world contact. Detection never checks heading or overlap acceptance. The shared solver uses a BVH, continuous separating-axis translation and conservative angular subdivisions, including finite faces/undersides and initial overlap separation. `COLLISION_RULES` bounds repeated response and versions its tuning. Core disposes the world after its borrowers.

Optional `createDynamics({ track, collisionWorld })` returns an owned CPU service with `{ id, version, rulesId, createActor, step, reset, snapshot, restore, dispose }`, synchronously or asynchronously. Core awaits one service after the collision world and shares the same `dynamics` with the player and every rival. `src/physics/rapier-world.js` provides Rapier 0.21.0 dynamics over the authored static triangles, with CCD, friction, angular response and static-only racer collision filters. Geometry, engine version and solver rules join the runtime identity. Core disposes dynamics after its actor borrowers. Omission retains existing motion.

Optional `playtests: { jump: { scenario, label, description, automaticRecovery?, cases? } }` selects an existing runtime/track scenario with `?test=jump`. Without `level`, that link selects Saffron. Start retains the normal audio gesture/countdown, while R, the pause restart and Repeat Case restore fresh solo scenario/device state. These sessions stay untimed across lap boundaries. Other URLs retain ordinary starts. The optional `automaticRecovery: false` flag is passed in the player runtime context as `playtest`; Saffron uses it to keep missed-jump physics running until R, without an automatic checkpoint transfer. Normal circuit recovery stays timed. Saffron's `jump-playtest` has a measured 320 m grounded runway for its second vertebra; the existing Vector strip/manual boost supply normal launch speed.

Optional `cases: [{ id, label, scenario }]` declares named existing scenarios, with unique IDs and a case matching the default `scenario`. `?test=jump&case=<id>` selects one; the title/pause selector and R use the selected case. Only playtest URLs expose `window.__VN.test`: `cases`, `reset(id?)`, `step(ticks, controls?)` and `getState()`. Reset restores the selected case with seed 7 and pauses it. Step requires a paused, ready session and 1–600 fixed 120 Hz ticks; it uses the live session advance and input log, preserving replay. Controls default to neutral and use the shared throttle/brake/steer/boost/airbrake fields. Results contain case/scenario, app/runtime identity, mode/tick, vehicle/motion state, events and errors. The visible selector and this API share cases without a browser-runner dependency. Saffron supplies `approach` and `short-fall`; arbitrary world-position launches remain outside this setup API.

## Session adapters and replay

Core calls `createRuntime({ track, collisionWorld, dynamics, scene, ship, host, settings, emit })`, or the ordinary `createMagneticRuntime` when omitted. Core composes shared devices around the returned adapter when `racing` is declared; flight/hazard motion remains level-owned. Preserve physics version 3 and steering assistance 0.3.

The returned adapter supplies:

- `id`, integer `version` and string `rulesId`: deterministic compatibility identity used by replay, snapshots and race records. Change identity when layout/rules or callback behavior changes.
- `scenarios`: optional dictionary of `{ label, state }` for deterministic verification setup. The paddock starts full-circuit practice.
- `advance(state, input, dt, modifiers?)`: complete vehicle advance, returning ordered events. Core calls it at 120 Hz instead of calling physics directly. Advance `state.time` exactly once per tick, including timed recovery. Racing adapters forward per-call `propulsion` and `shield` modifiers into grounded physics; shared flight also honors shielded edge impacts.
- `reset({ reason, state, scenario, seed })`: reset owned simulation for `initialize`, `fresh-lap`, `scenario`, `manual-recover`, `home` or `ship-change`. Manual recovery clears active effects/flight but may retain consumed-device eligibility. Pause/resume does not reset simulation.
- `snapshot()` and `restore(data)`: JSON-serializable simulation state, excluding meshes, audio and DOM. Core exposes it at `getSnapshot().runtime.state`.
- `pose(alpha)`: `null` for magnetic motion, or interpolated world `{ position, quaternion, grounded? }`. Ship +Z is forward, +Y is up; core and camera consume the same pose.
- `update({ state, dt, time, mode, camera, settings })`: presentation after pose/camera, once per rendered frame in all modes, including inspection. Use zero dt outside racing and simulation time; never mutate simulation.
- `dispose()`: idempotent release of exclusively owned resources, listeners, DOM and audio. Supplied scene/host/ship resources remain borrowed.

`advanceSession` calls adapter advance, emits its events, then steps the race with old/new distance and those events. With shared dynamics, motion adapters additionally expose `beginAdvance(state, input, dt, modifiers?)` and `finishAdvance(state)`. Device wrappers forward these hooks conditionally: expiry, brake cancellation and shields precede staging; impact consumption and new contacts follow resolution. Session stages the player and enabled rivals, calls `dynamics.step(dt)` once per 120 Hz tick, then resolves adapters and race timing. Ordinary `advance` remains available to standalone callers and performs its own bounded staged steps. Core saves previous vehicle state, logs input and advances the shared live/replay tick. Factory `emit` is for presentation feedback outside deterministic advance; deterministic events return through the advance hooks.

Replay includes application/track/physics versions, runtime identity, ship identity/version, seed, scenario, competitive mode, difficulty and complete tick inputs. `initial: { vehicle, runtime, dynamics? }` is captured after deterministic reset; playback rejects nonfinite or mismatched initial state, then restores it through the adapter. Countdown wall time is excluded. Replay also checks the untimed playtest flag. Competitive replay advances the same rival field, and failed initialization restores the prior session/field and complete engine state. Core owns one JSON engine snapshot, including solver state and all actors, rather than duplicating it in each adapter. Full resets rebuild dynamics before resetting actor runtimes; manual recovery resets only its actor. Manual R recovery invalidates the lap and prevents clean input-only replay; automatic flight recovery counts elapsed time without that manual-reset penalty. Race history remains scoped by rules and ship.

Flight adapters hold unwrapped distance at takeoff and emit `jump-transfer` with `{ id, from, to, outcome: "landed" | "recovered" }`. Race validation credits only the named jump's authored takeoff/landing/recovery interval and ordered checkpoint; an arbitrary skip is rejected. The [shared flight contract](#shared-local-mechanics) defines supported landings and level-local forces.

## Shared racing and automatic devices

New production levels declare `racing: { createDevices, createMotion? }` on the descriptor. `createDevices(track)` returns a stable layout of `{ id, type: 'vector' | 'aegis', distance, lateral, width, length, label }`. Keep authored metres/labels in the level's `devices.js`; use `src/pickups/layout.js` to validate bounds and keep hardware out of jump/recovery corridors. Shape review disables devices and racing. An optional presentation-only `signalScale` in `(0, 1]` attenuates Vector emitters in bright or enclosed circuits; it does not change contacts, speed or replay physics.

`createMotion({ track, collisionWorld, dynamics, settings, presentation: false })` creates a fresh CPU-only adapter for each rival. Omit it for ordinary magnetic motion; flight/hazard levels use the same pure motion factory as the player. Forward `advance`'s fourth modifiers argument. Avoid meshes, DOM, audio, shared mutable state or replacing the player's presentation lookup from CPU factories. The player retains the descriptor's original adapter/overlay references; core wraps that adapter with shared owned device presentation.

Core uses `src/pickups/runtime.js` for deterministic device composition and `src/race/racers.js` for the field, grid, input decisions, difficulty, relative gaps, two-lap classification and serialization. Each racer owns separate motion, device, reserve and lap state. Rival meshes consume `runtime.pose(alpha)` during true flight. Shared countdown/HUD/results and renderer launch feedback require no circuit-specific reimplementation.

The wrapper preserves local scenarios and adds device approach scenarios. Snapshots retain device fields at the top level and the complete custom adapter under `motion`; identity includes the motion rules and layout. Optional `racing.identity` supplies a deliberately preserved compatibility identity (used by Halcyon), and `racing.scenarios` can add diagnostic setups. All production circuits, including Nacre, require this shared system.

## Rendering and camera options

Backdrop result: `{ group, sunDirection, dispose, ready?, update?, setOverview?, assets?, ownedTextures? }`. It owns its sky textures; `assets` may expose borrowed resources to the environment. `ownedTextures` supports resource accounting. Optional light values are `sunColor`, `sunIntensity`, `ambientSky`, `ambientGround`, `ambientIntensity`, `fillColor`, `fillIntensity`, `environmentIntensity` and `far`.

Backdrop `update` receives the same frame during play. Reflection initialization also calls it with camera/settings/time/mode/reset, before vehicle presentation is available; handle that stationary case. No update occurs inside the regular draw call. Nacre's old multi-hook environment is adapted to a single update in its descriptor.

Descriptor `renderer` supports `world` (diagnostic name), `background`, optional `fog: { color, density }`, `bloomStrength`, `bloomThreshold`, `fillHeight`, `reflectionFar`, `transmissionResolutionScale` (default 1), `catapultBlurScale` (default 1, clamped 0–1), and `contact` options. Transmission scale changes the refraction buffer resolution independently of the main view. The selected factory owns sky/world identity; no Halcyon panorama is silently applied to new levels. High/low and reduced-motion settings remain shared.

Descriptor `camera` optionally sets `preserveFlightView`, `portraitAspect`, `maxPortraitScale`, `chaseHeight` (default 5 metres), `chaseDistance` (default 12.5 metres) and `lookAhead` (default 35 metres before the speed contribution). These three metre values can also be pure `(track, state)` callbacks for route-local composition; Zephyr smoothly pulls the camera back and upward while looking into the cloud spiral. Callbacks must return finite, continuous values without mutating simulation state. Numeric defaults and other circuits are unchanged. Saffron uses a higher eye and longer preview through rolling crests. Default chase behavior is unchanged; Nacre explicitly opts into its approved flight/portrait composition. Camera code does not infer behavior from track names. `jumpPreview: { distance, height, back }` opts into a smooth elevated view before declared takeoffs: the first half of the approach blends eye height/back distance and modestly aims toward the receiving deck. Free flight preserves the incoming composition when `preserveFlightView` is enabled. Umbra uses this to expose both lower landings before commitment. `flightViewScale` (default 1) gradually scales the carried eye offset over 0.8 seconds after takeoff, preserving its orientation and the first flight frame; Umbra uses 0.67 to restore craft proximity after the elevated approach. `flightChaseBlend` (default 0, bounded 0–1) gradually blends the carried position/orientation toward forward flight chase between 0.25 and 1.25 seconds; Umbra uses 0.78 to ease arrival back toward the racing view while preserving takeoff continuity.

A descriptor may opt into `camera.safeFrame: { left, right, bottom, top }`, an ordered rectangle in normalized device coordinates within `[-1, 1]`. It may instead be a pure `(aspect) => rectangle` callback for responsive HUD clearance; the returned rectangle is validated when used. Core supplies cached ship bounds and the actual displayed ship pose. During grounded chase only, the camera minimally corrects pitch/yaw when those bounds leave the rectangle; its eye position, field of view, road clearance, physics and ordinary look-ahead remain unchanged. Rotation damping targets the fitted aim, then a final correction keeps moving bounds inside the rectangle. Fitting the goal before smoothing prevents frame-time-dependent idle oscillation; damping restores ordinary aim as space permits. Free flight carries the incoming composition, including a corrected grounded view, and landing retains the existing gradual handoff. Inspection/vista and levels omitting `safeFrame` keep their existing behavior. Verify full hull framing and angular continuity through authored tight bends, impacts and flight/landing transitions; this guard does not solve scenery occlusion or an eye inside the ship.

## Track and review contract

Use metres, seconds and radians. Supply unique `id`, `name`, positive finite `length`/`width`, ordered `checkpoints`, contiguous named `sections`, `scenarios`, and `sample(distance)`. Track construction must work without a renderer for CPU verification. Checkpoints use `distance` or `s`; when both are supplied they agree, and an optional `index` matches the array order. Scenarios overlay fresh vehicle defaults, so omitted fields are valid; supplied distance/lateral/speed/heading values must be finite. Sampling wraps physical distance and returns finite `{ position, tangent, right, up, quaternion, curvature, bank }`, optionally unwrapped `roll`. Geometric +X (`right`) appears driver-left when facing +Z; preserve the existing input convention.

Production/shape share one track and its frames. A sampled route may include intervals without rendered road; flight/landing validity and scenery clearance need the level's own tests. The common route check does not require grounded motion. Sections use `{ id, name, start, end, showcase? }`; track and runtime scenarios remain available through the deprecated internal `window.__VN.loadScenario` verification API. Runtime scenarios may add `{ label, state }` entries. The paddock's Practice Lap starts a fresh full-circuit run. `review: true` enables fitted overview cameras, with 3D/top/profile buttons in shape review. Keep scenery/clearance rules local to the level. Optional [shared geometry helpers](../src/track/README.md) transport frames, sweep caller-owned profiles and test caller-selected clearance envelopes; they prescribe no world, material, terrain or route style.

The [reusable checks](../tools/level-checks/README.md) cover track/module contracts and short hidden runtime behavior, including failure cleanup, selected-asset isolation, controls, pause/reset, review UI and repeated disposal. Authored geometry, scenery clearance and driving still need targeted verification.

Own implementation files under `src/levels/<slug>/track/`, `environment/` and `backdrop/` as useful; those names are organization conventions, not additional required factories. Shared directories contain mechanics used across levels. Existing public asset URLs stay stable across source moves.

## Shared local mechanics

`src/physics/flight.js` exports `DEFAULT_FLIGHT_RULES` and `createFlightModel(overrides)`. A model returns `{ rules, sweptLanding, sweptRail, createRuntime }`; its swept-contact functions accept `(track, jump, beforePose, afterPose[, velocity])`, with velocity required by `sweptLanding`. Poses contain world `position` and `quaternion`. Only the authored receiving interval can catch a forward, upright descending hull. There is no invisible road across gaps or target-seeking flight assistance.

```js
const model = createFlightModel({ gravity: 26 });
const runtime = model.createRuntime(context, {
  id: 'my-level-flight',
  version: 1,
  rulesId: `my-rules-v1:${JSON.stringify({ track: track.geometryVersion, rules: model.rules, jumps: track.jumps, zones })}`,
  groundOptions: ({ state }) => ({ surface: sampleSurface(state) }),
  shouldLaunch: ({ jump, state }) => inOptionalLaunchLane(jump, state),
  airAcceleration: ({ position, time }) => sampleWorldForce(position, time),
});
```

The context requires `track`, optionally `settings`, the level-owned `collisionWorld` and shared `dynamics`; preserve steering assistance 0.3. The options require replay identity `id`, integer `version`, and `rulesId`. Include authored layout/rules revisions in `rulesId`, and bump identity when callback behavior changes. Optional `scenarios` uses the session contract; otherwise track scenarios receive plain labels. `edgeSource` optionally labels edge-catch impact events. No shared HUD, notice positions, scenario speeds, world colors or heat tuning are imposed on new levels. Nacre retains its own version-5 identity, scenarios, notices and rules through an adapter over this model.

With a collision world, the shared flight runtime resolves physical hits in both flight and falling recovery, then applies the same heading/support/receiving-interval acceptance rules. Only a supported contact transfers as `landed`; glancing contacts can continue flying and crash contacts start bounded recovery. Terrain/scenery cannot award a landing checkpoint. The world identity/rules are appended to runtime `rulesId`; impact payloads include `{ position: [x,y,z], normal: [x,y,z], collider, contactKind, response? }` for actual-contact feedback. Snapshot/restore includes collision cooldown/count and the reflected world velocity. Without a world, the legacy accepted-landing/rail queries stay unchanged.

With `dynamics`, Rapier owns airborne and falling-recovery position, quaternion, velocity and contact response. The adapter retains pilot forces, authored takeoff/landing acceptance, shields, events and bounded recovery timing. Grounded magnetic handling still uses `stepVehicle` with 0.3 assistance; grounded actors are inactive in the engine. After impact, recovery keeps the engine's angular motion and contacts until validated transfer. Upright, sufficiently supported top contact on the current receiving deck restores magnetic traction even after a rebound; this emits a `landed` transfer with `tractionRestored: true`, cancels the physical rebound and retains the small landing animation. Terrain, rails and undersides cannot restore traction during recovery. Actor snapshots retain game flight/pose/velocity state; session engine snapshots retain the complete shared solver state. Saffron opts into this path, while adapters without dynamics keep their legacy solver.

`track.jumps` may be empty. Each jump supplies `{ id, takeoff, landingStart, landingEnd, recovery, halfWidth }` in route metres. Jumps are ordered, non-overlapping and contained within a lap; the landing and recovery cannot wrap the finish. `halfWidth` describes the receiving road and must accommodate the craft. Exactly one checkpoint, at `landingStart`, is allowed between takeoff and the furthest of `landingEnd`/`recovery`. Invalid definitions fail at runtime construction. Route geometry and landing clearance still need level-owned numerical and real-input checks.

Mandatory gaps always launch. An authored optional branch adds `optional: true`, requires `shouldLaunch({ jump, state, input, from })`, and must retain a supported main road for the false case. The predicate samples the vehicle immediately before the tick crossing its lip; author clear lateral boundaries and matching geometry. A true predicate uses normal flight/landing; a false predicate uses ordinary checkpoint traversal. Optional does not bypass transfer validation once an airborne transfer occurs. Mandatory gaps retain the original strict transfer rule.

The flight adapter holds unwrapped route distance at takeoff, then emits `jump-launch`, `jump-miss` and validated `jump-transfer` events. Missed-jump recovery takes simulation time and preserves the valid timed lap; manual recovery remains invalidating through core. Snapshot/restore carries flight, world pose, settling and recovery state; reset clears them. Its `pose()` includes `grounded` during landing settlement. Presentation settings never change simulation.

`groundOptions({ state, input, dt, track })` is a **pure** sample passed to shared `stepVehicle`. It may be evaluated more than once when a tick splits at takeoff: do not increment timers, consume resources or emit events in this callback. The optional `surface` object contains:

| Property              | Meaning / default                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| `grip`                | Lateral response multiplier, default 1, bounded 0.05–4. Lower values preserve drift longer.    |
| `drag`                | Extra forward deceleration in m/s², default 0, bounded 0–100.                                  |
| `thrustScale`         | Engine multiplier for declared power loss, default 1, bounded 0–1.                             |
| `forwardAcceleration` | Signed route-tangent acceleration in m/s², default 0, bounded −100–100.                        |
| `lateralAcceleration` | Signed route-right acceleration in m/s², default 0, bounded −100–100. Positive is driver-left. |

These same per-call options are available on `stepVehicle(state, input, track, dt, { surface })` for grounded adapters. Omitted/invalid values use defaults; baseline steering, braking, reserve accounting and stationary magnetic hold remain intact. Declared forces act on moving craft; parked magnetic hold remains active. Zones, membership, surface IDs, enter/exit events, heat/cooling accumulation and visible moving boundaries belong to the level's deterministic wrapper. Store additional mutable state in the wrapper's snapshot/restore/reset methods, and keep all mutation in `advance`, never presentation or the pure samplers.

Grounded adapters may also pass `propulsion: { cruiseSpeed, thrust }` to `stepVehicle`. Finite values are bounded to 112–200 m/s and 42–2000 m/s². The stronger active manual/road profile supplies speed/thrust; manual boost still spends reserve, and braking cancels road propulsion. The shared device wrapper uses this for Vector catapults; ordinary motion retains its existing profile when omitted.

`airAcceleration({ state, jump, position, velocity, time })` is an optional pure world-force sampler. It returns a finite `{x,y,z}` vector, added to gravity and limited pilot control in flight. Position and velocity are copies; treat state as read-only. It does not affect automatic missed-jump recovery. Curved leaps need authored clearance and landing envelopes; the helper does not aim at the receiving road. Flight rule overrides are finite nonnegative numbers (positive dimensions, timeout, settle duration and step); the step cannot exceed 1/120 second. Per-jump receiving rail heights use `railHeight: { [jumpId]: metres }`, defaulting to 0.9 m. `railOffset: { [jumpId]: metres }` extends only the receiving rail envelope beyond the usable deck edge to match outboard barriers; the default is zero. Road landings retain the authored width, and a supported rail hit uses the same inward bounce onto the deck.

`launchImpulse({ state, jump, position, time })` optionally returns a finite world velocity delta in m/s, sampled exactly once at real takeoff. Use it for an authored, visibly signalled launch interaction. It does not alter boost reserve. Its resulting velocity is part of the flight snapshot. The configurable miss bounds `missBelow` (23 m), `missBeyond` (18 m) and `missLateral` (55 m) measure receiving-frame separation before timed recovery; curved paths must set bounds from their measured flight envelope and retain a bounded `timeout`.

Optional split decks must supply per-call `roadBounds: { min, max }` from `groundOptions` while the grounded route narrows. Bounds are geometric route-lateral deck edges, inside the full track width and at least the craft's diagonal hull width (about 8.33 m) apart. The swept hull collides with these asymmetric rails and returns `impact.payload.railLateral` for accurate shared sparks. Omission retains full-width rails. Invalid bounds are ignored, so validate authored bounds in level tests. Build a visible divider/taper matching the bounds; selecting no launch must never allow later sideways driving over the missing branch strip. Bounds affect grounded travel only, not a launched trajectory or the full receiving shelf.

Shared model defaults include `curvedContact: true`: if the cached plane sweep finds no landing, it brackets the descending hull against independently projected points on the actual curved receiving surface. This closes isolated speed/phase contact holes without enlarging the landing or accepting upward/underside contacts. Nacre explicitly uses `curvedContact: false` to retain its approved version-5 replay/contact behavior. Keep this model-rule value in the level's `rulesId` serialization; adopting the changed default changes compatibility for recordings using that contact mode.

`ui.compactLandscape: true` enables the compact HUD layout. At heights up to 570 px it separates the upper-right minimap, lower telemetry, left collapsed review toggle and centered expanded review panel, including 640×360. Shared transient notices use the upper center at 48px, clear of the chase craft. Touch controls remain visible across the short-landscape width range, including 844px; coordinate level-owned overlays with the notice band. It also keeps shared portrait notices above bottom telemetry and below review controls at portrait heights of at least 700px; desktop layout remains unchanged. At desktop sizes above 760 px wide and 700 px tall, it also separates the section label, expanded review controls and minimap into consecutive vertical regions. Approved circuits do not opt in automatically.

With curved contact enabled, the solver compares road and rail hit fractions before resolving either. An earlier supported deck contact wins; a later rail must not restart the landing sweep underneath the deck. `model.rules.contactVersion` is fixed by the shared model and must remain in the serialized rules identity when adopting solver changes. Nacre's explicit legacy contact mode preserves its existing order.

`ui.portraitCompactHud: true` reserves an upper HUD for portrait viewports up to 760px wide and at least 700px tall. Reserve/speed telemetry starts at 272px and transient notices at 330px, leaving the lower chase craft and touch controls unobstructed. Expanding review moves telemetry to 468px and notices to 420px below the panel. Keep level-owned guidance in the notice band, suppressing it while a transient notice is present. Desktop and landscape layout are unaffected by this flag. It is optional and defaults off; approved circuits retain their existing positions. Vesper opts in, with surface information at 156px and jump guidance sharing the notice band.

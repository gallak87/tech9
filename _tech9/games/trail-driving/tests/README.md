# Trail Driving verification

Run package commands with supported Node 22.13+ (22.x) or 24+. From the repository root, `./_tech9/run --prefix games/trail-driving run <script>` selects a supported local runtime. Install package dependencies with `./_tech9/run --prefix games/trail-driving ci` first.

| Command                                                     | Coverage and output                                                                                                                                                                                        |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm test`                                                  | 50 CPU checks for motion, contacts, sweeps, jumps/recovery, input lifecycle, trial rules, records, world queries, model/resource lifecycle and copied renderer contracts.                                  |
| `npm run lint`                                              | ESLint and package formatting.                                                                                                                                                                             |
| `npm run build`                                             | Production Vite bundle.                                                                                                                                                                                    |
| `SCENE_PORT=4482 npm run verify`                            | Builds, starts strict preview, drives all vehicle/camera and state transitions, checks responsive UI/resources/errors/production hook absence; `.artifacts/verification/`.                                 |
| `SCENE_PORT=4482 npm run verify:handling`                   | Real keys after targeted rare-state arrangement: collision, reverse/brakes, rough ground, takeoff/grounded landing and recovery for all vehicles; hidden audio and denied storage; `.artifacts/handling/`. |
| `SCENE_PORT=4482 npm run verify:routes`                     | All nine normal-speed keyboard runs, every gate/result/retry, record persistence; `.artifacts/acceptance/`. Takes about 15 minutes.                                                                        |
| `SCENE_PORT=4482 ART_ROUND=art-capture npm run capture:art` | Built garage/trail/driver/pause/settings/narrow stills; `.artifacts/art-capture/`. Scenic arrangement is art evidence, not completed-run evidence.                                                         |

Browser scripts close their browser and task-owned server in `finally`. The preview default is 4481; set `SCENE_PORT` to an available strict port. `SCENE_URL` reuses an existing server without owning it. `CHROMIUM_PATH` chooses a browser; `HEADED=1` makes it visible. The harness prefers installed full Chromium, which used Metal on this host; Headless Shell can use software rendering. Install Playwright Chromium only if no compatible installed browser is available. Serialize browser/GPU work.

`window.__SCENE_TEST__` exists only with `?test=1`. It provides readiness, independent snapshots, routes, world descriptors, terrain height, settings and targeted `arrange(pose)`. The nine-run feedback driver reads snapshots and sends keyboard events; it never calls arrange or writes time/progression. Rare-state tests and art captures may arrange poses and identify that evidence separately. The copied baseline browser scripts are retained as source history; the current package verification commands above target the driving game.

Frame reports include browser version, executable, GPU, viewport/drawing buffer, preset and requestAnimationFrame intervals. These include browser scheduling and do not isolate GPU cost or promise performance on other devices. Local evidence is ignored; durable results and limitations are in the [game README](../README.md).

## Vehicle-focused art inspection

`SCENE_PORT=4482 VEHICLE_ROUND=vehicle-art npm run capture:vehicles` builds and captures the actual park at fixed front/rear/both-side/detail camera poses, each garage and driver view, close mounted steering poses, a short real-keyboard turn strip and targeted terrain takeoff/landing pairs. Tight ATV/bike leg views cover both sides at rest, steering, takeoff and landing to expose rider/body/peg/exhaust intersections. Set `RECORD_VEHICLE_VIDEO=1` to retain the continuous capture as WebM alongside the PNGs. The report records the source commit, browser/GPU information and any graphics errors. Every browser/server is closed when the capture finishes. This capture does not drive full routes or replace the earlier nine normal-speed route completions.

Inspection poses exist only behind `?test=1`; normal production exposes no camera inspection hook. Eight asset regressions verify that the rebuilt models preserve all wheel world contacts, finite mounted/geometry transforms and exactly-once owned-resource cleanup while retaining the shared borrowed reflection texture. Geometry ray checks also keep both boots planted above the actual rendered platforms/pegs during steering and airborne poses.

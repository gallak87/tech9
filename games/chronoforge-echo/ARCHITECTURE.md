# Chronforge Echo — implementation contract

Standalone Vite 8.3.0 + JavaScript modules. PixiJS 8.16.0 presents a 1920×1080 artwork surface using a fixed 960×540 logical view. The finer backing surface and filtered display scaling preserve source detail without changing world scale or input coordinates. HTML supplies accessible text and instrument controls. Browser desktop, 16:9 letterboxing, keyboard first. No source or save namespace is shared with the reference. Node22.12+ is required; verification uses bundled Node24.19.

## Ownership
- Integrator: `main.js`, `ui.js`, `style.css`, `audio.js`, persistence/input, harness, integration.
- Environment builder: `world.js`, `art.js`, assets/provenance. Author all eight regions and interiors; render production pixel artwork and actors.
- Combat builder: `combat.js`, combat tests. Pure authoritative outcomes separated from draw calls; no DOM.
- Content builder: `content.js`, `progression.js`, `narrative.js`, NARRATIVE.md. Hero/item/skill/enemy catalogs, quest scripts, settlement rules.

## Units and public contracts
All time deltas are **seconds**, positions logical world units. Outdoor regions 5760×2520 minimum (6×4.67 viewports). Heroes approximately 48×78; map grid 24. Scene IDs stable, default era only. IDs snake_case, base namespace implicit; future registration accepts namespaced content without implementing it.

`state` is serializable: `{version:1,seed:9127,rng:9127,playTime:0,region:'haventide',x:525,y:1325,facing:'right',heroes:[hero],resources:{food,ore,energy,renown},inventory:{itemId:count},buildings:{town_center:1},tier:1,flags:{},quests:{},cleared:{},pickups:{},visited:{haventide:true},fog:{},settings:{music:.4,sfx:.6,timingAssist:false,reducedMotion:false,minimap:true},campaignComplete:false}`. Hero `{id,name,level,xp,skillPoints,hp,mp,equip:{weapon,armor,accessory},skills:[ids]}`. `stats(hero,state)` returns `{maxHp,maxMp,str,int,tec,def,spd,crit}`. Effective stats computed, never cached into saves.

Content exports `HEROES`, `ITEMS` object `{id,name,slot,stats,price,tier,description}`, `ENEMIES` object `{id,name,tier,hp,str,def,spd,xp,drop,description}`, `TECHS` object `{id,name,heroes:[ids],mp,power,stat,target:'enemy'|'allEnemies'|'ally'|'allAllies'|'self',effect:'damage'|'heal'|'shield'|'drain'|'slow',cost,requires,description}`, `BUILDINGS`, `TIERS` string array. Progression exports `createState()`, `stats(hero,state)`, `awardXp(state,amount)`, `recruit(state,id)`, `equip(state,heroId,itemId)`, `unequip(state,heroId,slot)`, `learn(state,heroId,techId)`, `build(state,id)`, `advanceTier(state)`, `production(state,dt)`, `buy(state,itemId,quantity=1)`, `sell(state,itemId,quantity=1)`, `futureEligibility(state)`. Mutators return `{ok,message,rewards?}`. Rewards array `{id,label,amount}`. No rendering/DOM imports.

World exports `REGIONS`, `getScene(id)`, `isWalkable(scene,x,y)`, `nearby(scene,x,y,state)` returning interactables within 50px, `terrainAt(scene,x,y)` ground/water/path. Region `{id,name,subtitle,biome,width,height,spawn:{x,y},town:{id,name,x,y},roads:[[{x,y}]],objects:[{id,type,x,y,w?,h?,solid?,name?,dialogue?,item?,enemies?,to?,spawn?,requires?}],portals:[same]}`. Object types town, house, cave, tree, rock, ruin, landmark, npc, encounter, pickup, sign, camp, console. Encounters have `enemies:[ids]`, unique `id`, optional `guard:townId`, `boss`, `flag`. Portal/door `requires` is a flag string or `{tier,flag}` and `.to` is scene ID. Town scene IDs `haventide_town`, `emberline_town`, `orbital_reach_town`, `last_crown_town`. Art exports `drawWorld(ctx,scene,camera,time,state)` terrain+props, `drawHero(ctx,id,x,y,{time,moving,facing,pose,scale})`, `drawEnemy(ctx,id,x,y,{time,pose,scale})`, `drawPortrait(ctx,id,x,y,size)`, `drawIcon(ctx,id,x,y,size)`, `drawBattleBackdrop(ctx,biome,time)`. Actor positions are foot anchors; art has no gameplay mutations. Integrator draws heroes over world. Scene solids are exact footprint tests; roads and portals remain passable.

Combat exports `createBattle(state,encounter)`, `updateBattle(battle,state,dt)`, `battleKey(battle,state,key)`, `battleClick(battle,state,x,y)`, `battleIntent(battle,state,intent)`, `drawBattle(ctx,battle,state,time)`, and `battleView(battle,state)`. Battle holds `heroes`, `enemies`, stable `readyQueue`, `selectedHero`, `phase`, `mode`, `cursor`, `target`, `action`, `result:null|'victory'|'defeat'|'retreat'`. No persistent reward application; integrator consumes result once. `BattleUI` in `battle-ui.js` renders the folding command overlay from `battleView`; the canvas retains the arena, actors, effects, and scene targets. DOM actions pass through the same authoritative intent path as keyboard input. Enter/Space/Right confirm, Up/Down navigate, Left/Backspace cancel, Tab selects the next ready hero. Escape is owned exclusively by global pause. `updateBattle` is never called during global pause. The authoritative action timeline owns anticipation/timing opportunity/contact/recovery; presentation cannot advance gauges or resolve outcomes. Fresh keydown only; one timing attempt per action, execute press never reused. Seeded RNG state is consumed only by outcomes. Damaging enemy actions temporarily open the shared timing slot. A fresh timed reaction reduces that incoming attack’s damage by 85% without spending ATB or granting a persistent guard stance; it uses the stronger guard rather than multiplying with an existing stance. Charge-only telegraphs do not offer a guard window. Enemy actions serialize `returnSelection` (mode, companion, cursor, target and pending choice) and restore it after recovery; an invalid/fallen selection returns to Crew. Attack critical chance is boosted only by hero attack timing, never by defensive input.

Narrative exports `SCENES` dialogue `{id,speaker,text}` arrays and `interactStory(state,objectId)` returning `{lines:[{speaker,text}],choices?:[{text,flag}],recruit?,rewards?,battle?,flag?}` with state progression allowed; `mainObjective(state)` returns string; `questList(state)` array `{id,title,kind,stage,objective,complete,reward}`; `onEvent(state,type,id)` advances declarative prerequisites/rewards once. Event types interact, victory, visit, build. Return results with lines/rewards as needed. Integrator checks story results and shows dialogue; root owns close/choice UI.

## Simulation and persistence
One RAF clock clamped at 50ms; simulation freezes under menu/dialogue/vendor/construction. Audio separate real-time bus. Followers sample the traversed path every3px at72/144px spacing, compress safely at doors; never chase through solids. Unique pickup/encounter/quest reward ledgers. Three manual save slots + checkpoint, versioned migration and validated load; localStorage prefix `chronforge_echo_v1`. Corrupt saves visibly reported. Test hooks only enabled via `?test=1` in Vite development; `window.__ECHO_READY__` after required content loads and `__ECHO__` deterministic presets/state inspection. Production has no test shortcuts.

## Art import and instrumentation

`assets.js` declares required source files, validates sheet geometry, reports decoded memory and failures, and installs atlases into the live `art.js` module. The Kaida RGB export uses connected exterior neutral-key interpretation at import; protected interior white pixels remain intact. Original generated PNGs are immutable. Frame crops use measured component bounds when generation does not preserve exact grid alignment. Actor foot anchors, visual extents, and collision footprints are distinct. `__ECHO__.snapshot().artMetrics` reads the live renderer caches, avoiding duplicate Vite HMR module instances in measurements.

`drawForeground` redraws props that lie in front of actors, with restrained translucency where foliage occludes a party member. `rendering.js` owns the 2× artwork backing scale, filtered contexts and logical texture-pattern sizing. Ground chunks occupy 384×384 world units with 768×768 backing pixels; the cache is bounded to 40 chunks (90 MiB). The Pixi presentation texture is 1920×1080 RGBA. Source atlases and ground caches are measured separately. Raw sprite extraction/mask canvases retain source resolution and are never scaled before cropping.

Named metadata modules separate hero poses, directional hero gait, ordinary enemies, middle enemies, bosses and regional scenery. `assets.js` composes their required entries and loads independent sources in parallel. Explicit source dimensions and measured frame bounds are validated against immutable PNGs; nonintegral generated grids do not override authored crops. Per-source neutral thresholds and measured interior background seeds remove checker gaps while preserving pale costume highlights. Import exclusions apply only to a private affected frame, never to the shared original source. No generated image is fetched from an external service at runtime.

The final action timeline uses one contact resolution for costs, HP, timing and effects. Rendering derives stance, target exchange lanes, shield launch, support poses, refracted blade ribbons and the coordinated dawn effect from that same clock. Spell effects and contact lanes are presentation, not changes to hit detection or combat outcomes.

Ending persistence distinguishes Architect victory, pending ending dialogue, the ending panel and completed homecoming. `endingProgress` retains the exact dialogue index or panel; completion and future eligibility are granted only by the actual ending return action. Loading/restarting clears prior-session held keys, gateway transitions and queued visual notices while leaving manually saved records intact.

Sign interactions route directly to `UI.showReading`, with object title/text and no speaker portrait. Escape dismisses the visible layer in order: input capture, confirmation, atlas, then service/reader/conversation/ending. Dialogue cancellation never calls its `done` callback or executes a choice. Ending dialogue is marked explicitly so ordinary conversations cannot overwrite its saved index. The suspended ending has a world HUD resume action; resuming is disabled in battle and during transitions.

Click navigation uses a 24px search grid with edge collision samples at most 3px apart. Search proximity is not arrival: if the requested floor position has a clear final segment, the route includes that exact endpoint. This prevents grid rounding from leaving the player outside a nearby service's interaction radius. Keyboard movement remains continuous and uses the same collision predicate.

Interior atlas positions resolve to their exterior doorway, preserving the crew marker while inside. Loading and restarting apply saved restrained-motion presentation as well as game state. Party/Quest reading supports Up/Down and every atlas/service page supports PageUp/PageDown/Home/End; shop comparisons include statistics lost with the old equipment.

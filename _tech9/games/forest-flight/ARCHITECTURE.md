# Forest Flight architecture

One metre is one world unit, +Y is up, and heading zero faces −Z. Positive heading and bank turn right. The game owns its copied code, assets and package dependencies.

- `src/main.js` supplies the flight valley definition and registers the world and gameplay controller.
- `src/core/SceneApp.js` owns the Three.js renderer, sky, lights, settings, single frame loop and layer lifecycle. The flight renderer uses the baseline HDR atmosphere/contact pass with MSAA and a long camera range. Mist uses local terrain elevation; a 270 m shadow window follows the camera.
- `src/flight/FlightSimulation.js` owns aircraft state and substepped movement, throttle/drag, speed-dependent control and lift, body-axis quaternion rotations, bounded coordinated banking, stall response and terrain contact. The state exposes canonical Euler attitude for HUD/camera interoperability; rotations are never clamped. Stabilization is optional, and Space temporarily recovers upright attitude. This remains an arcade approximation, not a force-based aerobatic simulator. The two aircraft profiles drive distinct handling. Game rules track optional markers, landing completion, valley bounds and crash recovery.
- `src/flight/FlightInput.js` maps keyboard state to normalized control intent and releases listeners/held input on cleanup. Focus loss requests pause.
- `src/flight/FlightGame.js` owns session UI, state transitions, aircraft selection, audio, camera integration and one visual aircraft. It supplies the active controller to SceneApp, advances simulation before camera tracking and disposes its listeners/resources.
- `src/flight/FlightWorld.js` owns airfield content, clear approaches, markers and obstacle integration.
- `src/flight/LandscapeLayout.js` owns the continuous height query, finite deterministic tree placements/spatial index and seeded 32 m undergrowth tiles. The same tree placements drive detailed meshes, distant canopy, shade field and collision queries.
- `src/flight/Landscape.js` owns rendering and resource disposal: one uniformly sampled 6.4 km terrain mesh, fixed forest impostor batches and reusable nearby instance buffers. The traversable valley remains 4.8 km; the extra terrain/canopy softens its boundary. Baseline GLB prototypes, PBR ground textures, alpha coverage, transmission, wind and soft shadows are reused. Trail color, normal and roughness blend together with texture-driven edges; moss coloration resolves only near the camera. Tree density and ground cover use the same irregular grove field, and tree size/tint vary in spatially coherent stands. The airport verge uses shorter, patchier grass. Sixteen azimuths and four elevations are baked per pine into one 3072×2304 atlas; near trees blend over 180–220 m. Full grass blends to the baseline reduced grass mesh over 16–28 m; that cheaper, Lambert-lit grass fades over 70–96 m. Other undergrowth fades over 32–66 m. A 7×7 tile window and altitude-aware tree selection refill existing buffers when the camera changes 32 m cells. No travel-time construction of geometry, material or texture objects and no unbounded tile cache. Existing resources may upload or compile on their first visible frame; counts then settle. Shader variants are fixed. High/Ultra increase undergrowth density over Balanced; tree LOD uses complementary sample masks so the two representations cover different pixels; all presets retain four-sample alpha coverage.
- `src/flight/AircraftVisual.js` authors both meshes and cockpit panels, animates propellers and control surfaces, and releases unique geometry/material resources. The caller owns its world transform.
- `src/flight/FlightAudio.js` owns a local Web Audio engine tone. It starts on a user gesture, follows throttle, silences on pause and closes its context on disposal.
- `src/modules/follow-camera` supplies copied chase and mounted camera behavior. The game provides world-space target/pose data.

Assets load locally. Airfield terrain, aircraft and textures are authored in code; `art/` preserves the baseline forest kit sources. Baseline world/controller sources remain available as owned reference code; the running game selects only the flight world.

`?test=1` exposes read-only state snapshots and lifecycle disposal plus one rare collision setup. Success-path browser checks use normal keyboard controls from initial runway spawn through a complete circuit and landing. Test-only simulation-rate control accelerates travel; capture/performance and aerobatic observations return to normal speed. Camera-only `inspect` selects fixed art views without moving the player and is never used for success-path validation. Tests cover simulation, pause/focus input clearing, terrain/approach clearance and inherited renderer lifecycle contracts.

## Handoff / later framework-dev

Reusable candidates are deterministic spatial vegetation queries, fixed-capacity instance pools, prototype-view baking and distance coverage transitions, terrain-relative atmosphere, moving shadow coverage, and body-axis arcade flight with optional recovery. These remain game-owned pending the separately scoped framework-dev task.

| Existing system                             | Change needed for reuse                                                                                                                                                                  |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **flight-motion**                           | Quaternion/body-axis attitude, optional stabilization/recovery intent and inverted-flight tests. Keep circuit and landing-result rules in the game.                                      |
| **follow-camera**                           | Optional orientation/velocity target for near-vertical chase tracking; rolled mounted poses already work.                                                                                |
| **grounded-walking / placement-collisions** | Local collider-provider query instead of requiring the entire fixed-map array.                                                                                                           |
| **Baseline SceneApp / AtmospherePass**      | Inject local terrain elevation and caller-owned moving shadow bounds. Preserve renderer ownership and failure-safe teardown.                                                             |
| **New landscape candidate**                 | Deterministic spatial vegetation, fixed-capacity instance pools, atlas baking, matched near/far placement/tint, and layered terrain materials. No canonical landscape module exists yet. |

For landscape extraction, parameterize prototype names, atlas views, terrain/biome queries, quality budgets and distance bands instead of exporting this valley’s constants. Preserve failure-safe atlas renderer restoration and idempotent resource cleanup. Keep game markers, airport mowing, the trail route and circuit rules with the game. The baseline asset sources and licenses remain the foundation.

The fast review harness (`npm run verify:art`) captures fixed ground/low/high viewpoints, a short local camera sweep and repeated distant-region resource checks. It records the exact commit, browser/GPU, frame intervals and pool/resource counts. These observations complement ordinary keyboard flight tests; three transition stills do not prove temporal smoothness.

Limits: distant trees are view-selected impostors, so some view/LOD change remains visible; ground cover is a bounded near-camera effect. The heightfield is smooth 10 m tessellation with scanned normal detail, not an erosion/rock-cliff simulation. Conservative aircraft/tree contacts do not model individual branches. The chase camera stays horizon-level; cockpit follows aircraft orientation.

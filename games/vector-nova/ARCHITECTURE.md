# VECTOR//NOVA architecture

## Stack and module boundaries

Standalone Vite + Three.js ES modules, WebGL2, PBR/ACES and sRGB output. No repository framework, alternate launcher or cloned runtime. See the [README](README.md) for available circuits and the [roadmap](ROADMAP.md) for planned work.

The locally owned ESLint/Prettier/lint-staged/Husky configuration was adapted from Chronoforge Echo at the user's request.

| Module                 | Responsibility                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| levels                 | Validated discovery, per-level factories, metadata and presentation adapters              |
| core                   | Boot/readiness, fixed-step session, replay, mode changes and teardown                     |
| track                  | Optional route-frame, sweep and geometry mechanics                                        |
| environment / renderer | Optional placement mechanics; shared rendering, lighting and resource metrics             |
| ships / camera         | Selectable async fleet assets and local presentation; road-frame chase/inspection cameras |
| physics / race         | Vehicle motion and rail response; checkpoint/lap validation                               |
| input / ui             | Normalized controls, focus/visibility cleanup, menus/HUD/settings                         |
| audio / effects        | Event-driven presentation; failure must not stop simulation                               |
| pickups                | Shared automatic devices and owned visual/audio presentation                              |

`src/levels/<slug>/track/`, `environment/` and `backdrop/` own each circuit’s route, construction, materials, scenery and sky; Nacre also owns its overlay and flight presentation adapter. Shared directories contain reusable mechanics, never a default world style. Asset URLs follow stable level/ship folders; replay identities are independent of asset filenames.

`src/levels/` discovers asset-free metadata eagerly and imports only the selected implementation. Its [level API](docs/LEVEL_API.md) defines factories, presentation and ownership; unknown or malformed levels fail visibly.

## Front end and world ownership

`src/core/main.js` starts the asset-light `src/frontend/` shell directly on the scrolling circuit card library. At widths of 1200px and above, circuit cards, race mode/difficulty, the ship studio and vertical performance stats share one setup screen with a single Start action. Narrower screens reuse those controls in stacked Circuit/session and Ship accordion sections; mode selection advances to Ship, and either header reopens its section. Resizing preserves selections and focus. Start → Loading → Race → Results is the normal flow. Only Start constructs a world. Hover and arrow-key focus preview circuits/ships without changing the selected session; click or Enter commits, and leaving the list restores the selection. Circuit previews read cached stills; ship previews reuse the studio renderer and parsed model cache. Quick Race uses the existing two-lap competition; Practice is open solo driving. Ship selection displays the actual GLB in a fixed-size, drag/keyboard-controlled studio that draws only on model/view/size changes and releases its WebGL context on exit. CSS size containment keeps canvas resolution independent of layout. Settings includes the keyboard legend; lists use arrow/Home/End navigation and roving focus, alongside native Tab/Enter/Space controls. Explicit `?level=` links select a circuit without loading it; `?review=`, `?test=` and `?capture=1` retain the runtime/review entry for tools. `window.__VN` remains the current runtime API; `window.__VN_FRONTEND.getState()` reports shell and preload state.

`src/ships/model-cache.js` preloads Kestrel first, then the remaining player GLBs in the background. Concurrent demand loads share a promise; failed requests remain retryable. Parsed sources live for the page session, across world disposal. Each `createShip` clones source geometry/materials/textures into independently disposable presentation resources; cached sources never borrow a renderer or own uploaded scene resources. Page teardown releases the cache after worlds/previews. A shared status strip sits directly below the ship studio for fleet transfer/parse progress, and below the circuit hero during world construction. The collapsed Ship accordion row also shows preload status before that section opens. It is absent from driving and settings.

`src/core/game.js` exports `createGame({host, parameters, signal, onProgress, onMode, onHome, onResults, onCircuit})`. The shell serializes cancellation, disposal and world creation. Phase checkpoints yield between route/graphics/world/ship/warmup tasks and surface errors with retry/back. Individual synchronous constructors and first GPU submissions can still stall; this is not a complete M1 performance pass. One loaded world and one active session are retained: Escape pauses, Circuits suspends rendering/input, and Resume restores the same run or results. Browsing cards/ships does not mutate it. Only explicit Start calls `prepareSession()` before configuring a new chassis/run; starting a different circuit disposes the old world and WebGL context. All loading exits cancel through the same path. In-race inspection preserves its return mode and locks chassis changes. `src/progression/` owns one live settings snapshot; shell and runtime subscribe, including pause controls, and storage failure never breaks in-session synchronization.

Tunes belongs to the shell, outside world disposal, with one native audio element and a fixed top-right anchor. Track, position, queue and volume persist through loading and gameplay; expansion is available in menus/pause. Current audio uses automatic preload and stable asset URLs; initial construction buffers without playing, and a menu-button activation or explicit Play/M starts playback. Next-song switching and controls still need JavaScript; continuity under severe resource pressure requires separate performance testing.

### Circuit preview refresh

Circuit thumbnails are saved **640×400 WebP captures of the real pulled-back free camera at Low quality**; they are runtime assets, not live views or verification evidence. The capture enters free-camera mode (hiding racers/effects), backs away from the grid, lifts the camera and aims toward the route centre before saving. Hover only switches the saved image. `tools/menu-catalog.mjs` builds SVG route outlines/facts from CPU models and includes a still only when its file exists and its fingerprint matches `public/assets/menu/previews.json`. Missing/stale stills fall back to the current route outline; there is no browser-side recapture.

After final visual/source changes and formatting, from this app directory:

1. Use Node 22 and start a dev server on a free port: `npm run dev -- --port 5197`. Keep existing user servers untouched.
2. Refresh changed circuits: `VN_URL=http://127.0.0.1:5197 npm run previews -- halcyon nacre`. With no circuit IDs, the tool checks every circuit and skips current captures. `--force` recaptures even when the fingerprint matches.
3. For shared camera/rendering/ship/presentation changes, or borrowed assets used by variants, refresh all consumers: `VN_URL=http://127.0.0.1:5197 npm run previews -- --force`. Fingerprints cover shared non-UI source, ship assets, the capture tool, each circuit's own source and matching asset directory; they do not discover every cross-circuit/shared-level asset dependency, so the explicit refresh remains required.
4. Check the resulting menu images, run `npm run build`, and commit `public/assets/menu/<id>.webp` together with `public/assets/menu/previews.json`. Stop the server you started. Repeat the refresh if commit-time formatting changes fingerprinted source.

The capture tool opens its own headless browser, uses `?level=<id>&capture=1&music=0`, and overwrites one image per circuit plus the fingerprint manifest. Do not save parallel screenshots, capture logs or audit JSON. The shipped preview set and the separately retained user-requested art concepts are registered in [the asset manifest](docs/ASSET_MANIFEST.json).

## Route, coordinates and handling

- Metres/seconds/radians. World +Y up; ship local +Z forward, +Y up.
- `sample(distance)` wraps arc-length metres and returns `{position, tangent, right, up, quaternion, curvature, bank}`, optionally `roll`. Road, ship, camera and physics consume the same frame.
- The legacy `frame.right` is geometric +X, which appears driver-left when facing +Z. Positive input steer means driver-right: negative geometric heading/lateral displacement. Do not reverse this when adding levels.
- Reuse `src/track/frames.js` for continuous parallel-transport frames through vertical tangents/inversions and lap closure. Reconstructing every frame from world-up crossed with tangent fails at vertical directions. The optional [geometry helpers](src/track/README.md) retain authored profiles and local clearance rules; no shared world preset is applied.
- Track models expose unique/versioned identity, length, full width, ordered checkpoints, contiguous named sections, scenarios and bounds. Production and shape views share one route.
- Fixed simulation is 120 Hz, capped at 0.1 s / 12 catch-up steps. Pause/visibility loss clears the accumulator. Render interpolates distance and quaternion; presentation never mutates simulation.
- Bend assistance is 0.3. Persistent heading retains the unassisted yaw, while a separate steering response preserves manual turn-in. Pitch/roll adhere to the magnetic surface.
- Gravity projects through tangent/right axes; explicit parking hold prevents slope/bank creep. Yaw-aware swept rail bounds resolve collision, reserve loss and lateral response. Manual recovery clears heading and invalidates the lap.

Shatterline retains stable authored source addresses while its physical road folds back beneath earlier reaches. `distanceAt`/`sourceAt` convert source addresses and race arc length; `pointAtSource` returns actual world position. `spineZAt`/`sourceAtSpineZ` describe only the monotone scenery reference spine. Their compatibility aliases `worldZAt`/`sourceAtWorldZ` are not inverses of physical road Z. Placement near crossings must use actual three-dimensional road positions and branch clearance, with `nearestSourceAt` available for spatial ownership.

Halcyon uses a 5 km route with distributed rise/descent, full roll/inverted hold and plunge. Asterion uses 4.5 km with a wall ride, raised crossing and steep dive. Authored dimensions and section data belong in their models, not duplicated documentation tables.

## Session, devices and replay

`src/core/session-runtime.js` provides the ordinary magnetic adapter and one `advanceSession` path shared by live input and replay. The [session adapter contract](docs/LEVEL_API.md#session-adapters-and-replay) defines hooks and event order. Preserve identity `{id, version, rulesId}`; replay also checks app/track/physics versions, seed and deterministic initial state. Reject incompatible or incomplete logs.

Production descriptors declare `racing: { createDevices, createMotion? }`. Core wraps the player's existing motion adapter with `src/pickups/runtime.js`, and creates each opponent with that circuit's pure motion factory and the same device layout. `src/race/racers.js` supplies three independent vehicle/race/device states and deterministic steering, braking, manual boost and lane decisions. Rivals borrow the fleet's versioned handling profiles (Rook/Kestrel, Latch/Shrike, Mule/Bastion) while rendering their own GLBs. All four clocks start together on a 2×2 grid; rear-row travel to the start counts toward time without crediting a partial lap. Easy uses the baseline pace, Medium drives faster, and Hard drives faster again and earns boost usage from actual player boosting, spending its own reserve in suitable acceleration windows. Difficulty is fixed for the run. Solo practice and verification scenarios disable opponents.

Halcyon, Orbital, Nacre, Vesper, Glasswake, Cindercoil, Saffron, Umbra and Helion use this shared system. Nacre retains its approved version-5 landing solver inside the shared device wrapper. New circuits must declare the shared racing capability rather than implement independent devices, AI, countdown, HUD or results. Opponents render their actual interpolated flight pose and use their own reserve to reach required-jump launch speed; optional branches remain route choices. CPU adapters never own the player's local presentation ledger.

Human launches use the shared HTML/CSS start lights and three countdown beeps followed by a longer kickoff tone. `src/core/start-countdown.js` uses a pausable wall clock; vehicles, lap clocks and replay recording remain frozen until lights out. Throttle held during the countdown takes effect on launch. The internal verification restart/scenario API bypasses the countdown. Audio unlock failure cannot prevent launch.

Competitive runs latch each racer's first two checkpoint-complete laps and classify valid finishes by total time; invalid runs remain explicitly unranked. Practice never acquires a competitive finish flag. Three red start lights turn green on GO. `src/race/finish-marker.js` places a small shared checker mesh at checkpoint zero (or an open route's `finishDistance`), conforming to road banking; optional `racing.finishMarker` paint dimensions/tones remain level-local. Completion events pass through the shared tick's event stream to a distinct finish cue and headline. A 2.4-second track-visible finish beat brakes the player and gently widens grounded chase (no camera move in reduced motion), then fades in a compact track-backed results panel. Rivals retain independent clocks until they actually finish. Continue Driving preserves the recorded result; Pause can reopen Results, and recovery does not reopen it automatically. Audio keeps finish tails audible while stopping propulsion/environment in results. Replay records competitive/solo mode and difficulty and advances rivals through the same fixed ticks; rejected initialization restores the prior field and presentation flags.

The driving HUD shows position, lap count, personal current/last/best lap times and all four racers in race order. Relative gaps use YOU as 0.0s, negative for rivals ahead and positive for rivals behind. `src/race/relative-timing.js` retains bounded passage samples on unwrapped course distance, interpolating the leader's passage at the trailing ship's current point; gaps never subtract lap clocks or divide distance by current speed. Recovery/reversal clears that ship's passage history, unavailable gaps remain unknown, and replay rollback includes the samples. Recorded lap/total finish times appear in the paddock. Rival minimap dots and row strips share one stable color per identity; the player has an orange marker with a white outline.

Open courses opt in with `track.closed === false`; `finishDistance` is the final checkpoint and `length` includes safe runout. The race latches one grounded ordered finish, then supplies ordinary braking controls while each unfinished rival continues independently. Sprint HUD, open minimap markers and solo results reuse shared UI. Airborne presentation progress follows the real pose within its jump corridor and never grants checkpoints. Sprint identities include format, finish and geometry; field rollback retains validated transfer keys. See the [level API](docs/LEVEL_API.md#track-and-review-contract).

Vector strips apply a +65 m/s entry impulse at leading hull contact, capped at their 600 km/h target, and add strong propulsion only while the hull overlaps the strip. The per-call road profile can exceed the selected ship's manual boost; holding boost selects the stronger active profile and still spends reserve. Exiting removes the force immediately and retains actual vehicle speed; no timed boost or reserve charge remains. Sweeps include yaw, lateral entry and lap seams. Device ticks expire Aegis's six-second protection and apply brake cancellation before physics, consume shields on qualifying impacts, then sweep new contacts. A shield collected later in a tick cannot protect an earlier impact. Effects do not stack; manual recovery clears effects while retaining the consumed-device ledger. Reverse/parking/reset farming must not rearm devices. Shields protect reserve loss, not collision separation or speed consequences. Shared rules, geometry, presentation and audio live in `src/pickups/`; placement plans live in each circuit's `devices.js`. Ground devices do not trigger in flight/recovery. The motion adapter receives per-tick propulsion/shield modifiers; Aegis protects rail-edge reserve loss without changing airborne deflection or landing geometry.

The opt-in `src/physics/flight.js` model supplies ballistic flight, swept landings and timed recovery. Nacre's adapter retains its authored rules, identity, scenarios and notices. Level adapters may supply pure grounded surface/force and airborne force samplers; zones, heat and events remain level-owned. Per-call surface options default to unchanged magnetic response. Optional authored jumps retain supported main-road traversal; actual transfers keep strict landing-checkpoint validation. See the [level API](docs/LEVEL_API.md#shared-local-mechanics). Automatic missed-jump recovery counts its delay as elapsed time and retains a valid lap; manual recovery still invalidates it. Keep Nacre-specific tuning out of the ordinary magnetic adapter. Local flight, surface, hazard and force rules use versioned session adapters. Shared defaults remain compatible with existing circuits.

Levels can opt into `createCollisionWorld({ track })`. Core owns one CPU world before presentation and shares it with the player and independent rival runtimes. `src/physics/collision-world.js` indexes authored triangles in a BVH and sweeps the whole oriented arcade hull with continuous translation and conservatively bounded rotation. `src/physics/hull.js` centralizes its established dimensions/projection math. Physical detection precedes landing acceptance: heading, half-width support and the current jump interval determine relatching only. Rejected borders deflect along their actual normal; solid deck/scenery hits bump into timed recovery. Recovery keeps sweeping, with six contacts per substep and deterministic impact cooldown/state. Geometry and collision rules join replay identity; world contact positions/normals reach shared sparks and Aegis feedback. Levels without a collision world retain their existing path. The eight expansion flight circuits register exact production road solids around their jumps with level-owned selection; Vesper also bakes its placed landing bough from the production GLB. The shared extractor preserves gaps and instance transforms without depending on presentation quality. Cindercoil also registers its production deck, ramp-end faces, walls, keel and large supports in a bounded vent-jump corridor; distant scenery and the environment GLB remain outside that first pass. Racer body contact remains deferred.

Descriptors may also opt into async `createDynamics({ track, collisionWorld })`. Core owns one shared `src/physics/rapier-world.js` service and passes it to every motion adapter. Saffron uses pinned Rapier 0.21.0 for airborne and falling-recovery translation, rotation, friction and CCD against the same authored static triangles; grounded magnetic handling and 0.3 assistance stay unchanged. Session stages player/device/rival hooks, steps the engine once per 120 Hz tick, then resolves ordered events and race timing. Collision filters exclude racer body contact. Runtime identity includes engine/geometry/solver rules; replay initial state and failed-playback rollback retain one complete session engine snapshot. Full resets rebuild the world before actor resets, while manual recovery resets only the player actor.

## Ship and rendering

`await createShip({id, ...options})` returns `{group, update, dispose}`. `src/ships/catalog.js` owns asset-free ship identities, handling versions and tuning. `createFleetShip` retains a stable root for borrowed level effects while replacing and disposing the selected chassis; failed loads retain the current model. Core restricts switching to menus, blocks launch during loading, refreshes camera bounds and starts a fresh deterministic state. Selection persists when local storage is available. Vehicle state carries `shipId`; grounded physics reads its profile while steering assistance stays 0.3. Replays check ship id/version and lap rules are ship-scoped. Load the GLB before measuring inspection bounds, baking reflections or warming shaders. Core owns world pose; update animates only local presentation. Editable sources, concepts and provenance live in `assets/ships/<id>/`; runtime GLBs live in `public/assets/ships/<id>/`. Kestrel keeps its dedicated exporter; `assets/ships/build_fleet.py` builds the three additions. Both share `assets/ships/surface_finish.py` for original PBR and cavity-occlusion bakes. See [ship API](src/ships/README.md).

High uses single-sample HDR with sampled depth, localized exhaust refraction, GTAO, restrained bloom, OutputPass and SMAA. The renderer owns the half-resolution exhaust displacement field and its composite; it borrows visible plume transforms/pressure during each frame. Hull-space bounds plus scene depth guard foreground and craft pixels. Low, shape review and reduced motion disable the distortion. The plume uses simulation-time pressure/flow and is excluded from AO geometry. The shared radial world blur becomes strong on Vector contact, with a fast attack and clear vanishing point/craft center. High retains a subtler speed/manual-boost blur after launch; Low runs the blur/output/antialias passes only during catapult contact and otherwise renders directly. Blur is disabled outside racing and with reduced motion. Multisampled HDR plus GTAO caused an ANGLE Metal opaque-region fault; retain the working pipeline. DPR caps are 1.25 desktop / 1 mobile.

Sky PMREM and a static scene probe approximate reflections; these are not realtime reflections. Renderer-owned reflection textures are borrowed by ship/environment materials and must not be disposed by borrowers. Road coverage masks the analytic contact footprint over real apertures.

Camera damping follows transport through the road frame, with quaternion rotation and local road clearance to handle inverted decks and steep crests. Inspection fits the loaded ship's bounds to the available UI region. Pooled road lights use continuous fades; thin road details must follow the tessellated surface to avoid flicker.

Level discovery imports only the selected implementation. Fleet selection loads the selected player GLB; competitive circuit boot also loads its three rival chassis, and rival inspection owns a separate loaded instance. All runtime loaders use `src/assets/url.js` and respect Vite's base URL. Preserve ownership and readiness when normalizing paths.

## Lifecycle and verification

One owner releases each geometry, material, texture, listener, audio node and animation callback. `createLifetime` unwinds owners in reverse order on shutdown or failed boot; inspection owns only its floor/ring, and level components borrow renderer probes/sky textures. The shared presentation controller updates road, environment and backdrop once per frame, supplies zero dt outside racing and propagates resets. Camera flight/portrait behavior uses explicit descriptor options. Await owned assets and shader warmup before setting ready. Dispose must be idempotent; failed boot should show a useful reload error. Audio/storage failure stays recoverable, and context loss pauses.

Every circuit includes the shared free inspection camera: F or the paddock/pause Free Camera button enters from the current camera pose; drag-look, WASD/arrows and Q/E move through the full environment at a fixed 200 m/s. The `fly` mode freezes simulation, lap timing and replay recording, and hides the player, rivals, contact shadow and impact particles. Returning restores the prior racing/paused/title/overview/countdown mode and clears controls. Its keyboard/pointer/touch listeners are owned by `src/core/fly-camera.js` and disposed with the session.

`window.__VN` exposes readiness, snapshots/metrics, named scenarios, camera selection, start/pause/restart, replay and disposal for verification. Scenario placement is deterministic setup, not autopilot. Runtime metrics distinguish source geometry from drawn multipass totals.

Load only selected-level assets. The [common level checks](tools/level-checks/README.md) validate CPU track/module contracts and short hidden runtime behavior. Test high/low, reduced motion, pause/reset/replay, resource disposal and relevant real input after runtime changes.

## Nacre flight, water and moving scenery

The Nacre runtime owns ballistic flight, bounded air control and swept receiving-road/rail contact. Landing coverage is derived from the accepted 70%-through-boost launch envelope, including long receiving straights. Sweep the hull between ticks to prevent tunnelling; accept only the authored road and orientation. A forgiving half-width rail catch deflects the craft inward with one small penalty. Automatic recovery credits only its validated jump interval; ordinary manual recovery stays invalidating.

Keep craft, road and camera origins consistent at takeoff and landing. Transport the previous camera relative to the craft anchor, not between mismatched road-centre/world-pose origins; otherwise off-centre launches visibly jump sideways. Preserve the actual contact pose, then settle height/attitude smoothly. Both live input and replay consume the same advance routine and rules identity.

Water crossings use actual world height. Protect the mean-water road/contact corridors inside displaced storm waves, and apply underwater absorption to the scene, ship and HUD together. `audio.immersion(frame)` samples the listener's current camera height; a reusable output filter/gain blend covers propulsion, manual boost, thunder, race cues and the separate device-cue bus, including voices already playing during exit. Master volume and pause still control output. Seeded lightning/thunder and pooled splashes follow simulation time and obey pause/reset, mute and reduced motion. Four bounded bubble slots use the actual craft pose and flight mode for submerged takeoff, flight trails and landing; recovery teleports and navigation clear presentation history, and reduced motion hides the drifting bubbles. Environment geometry, not just its centreline, must clear banked roads and flight envelopes.

Moving creatures are presentation only. Reuse one loaded mesh, deform positions and normals by arc-length transport, and verify the full asset envelope. For a crossing, use a fixed world-space heading rather than successive route frames: following the road makes the creature turn alongside it. Stage the entire body across a viewing window with speed-scaled timing, including boost acceleration; a head-only or single-instant visibility check misses the intended spectacle. Keep reproducible asset sources and provenance; screenshots, critique scores and iteration histories are not architecture.

## Glasswake ice and weather

Glasswake owns its crevice/corkscrew route, alternate frost/crystal grip, paired ballistic jumps, calving scenery and presentation glass. Their versioned adapter rejects earlier geometry/rules replays. Production loads the selected sky, v5 Blender export and ice detail bitmap; shape review loads none of those environment assets. Ice template primitives consolidate into one opaque draw with vertex colour/roughness/response; special emissive and metal parts remain separate. Rubble ledges embed into their parent placed massifs. Near ice uses triplanar colour plus artistic roughness/derivative relief, and clear road panes retain transparency with visible image-derived cloud/vein masks and sparse seeded trapped-air clusters.

`src/levels/glasswake/weather/` is currently level-local. Weather samples the absolute simulation clock and contiguous cavern exposure, without changing motion or adding a separate loop. Two instanced flake volumes and a soft gust layer wrap around the view, and the owned overlay canvas reserves the centre and UI rectangles for visibility. Attached flakes are cached in small sprites and composited at 24 Hz plus exposure/layout changes; the full-screen canvas uses no blur or clip surfaces. Reserved UI regions are cleared after composition, including overlaps. Stronger exterior blizzard haze uses the existing exponential scene fog, without a new render pass. Pause, reset, review and reduced motion are presentation inputs; disposal removes the canvas and releases owned buffers/materials. Calving powder shares the shelf's absolute separation phase and belongs to the environment disposal traversal.

Glasswake’s opening Mouth vault is detached from the static batch as the first shelf collapse. Its version-6 runtime owns a once-per-session elapsed phase, emits one `glasswake-shelf` event at the forward Berth crossing, and snapshots/restores the phase with flight state. Lap crossings and manual recovery retain the fallen sheet; fresh sessions restore it. Named opening-sheet scenarios provide deterministic inspection poses without playing sound. The opening sheet partitions its original surface triangles into sixteen closed fragments within one consolidated draw mesh. A small exposed tip releases first, progressing into larger strips with absolute downward/outward poses; generated rough inner faces become visible only after release. The later calving event remains route-sampled from the second jump’s takeoff, projects the displayed flight pose, and uses a per-lap ledger to emit its sound on the actual second `jump-launch` tick. Seeking and recovery retain that ledger. The opening sheet and its bounded powder fall clear of the sampled road/camera corridor; moving geology is excluded from support anchoring. Original seeded crack/powder synthesis lives in the level and uses the shared audio bus through `audio.environment(context, bus)`, with master volume, pause/mute/reset and owned disposal.

Glasswake production road readiness is followed by a local environment construction pass: `anchorToTerrain` raycasts the placed closed geological meshes once, selects a contact clear of the sampled route/camera corridor, and embeds bundled legs/shoes there. It excludes moving scenery and detached fragments. The road owns those added buffers/materials; the environment lends its geometry only during construction. Shape review remains independent of environment assets.

## Cindercoil local mechanics and atmosphere

The Cindercoil backdrop loads the selected sRGB panorama before renderer readiness, uses continuous longitude derivatives and an overlap blend at the wrap, follows the camera and disposes the texture once. Shape review uses an asset-free neutral backdrop.

## Saffron fossil traversal and atmosphere

Saffron uses the shared flight/device adapter with its own gravity, rail geometry and required receiving intervals. The receiving straights accept the authored 600 km/h device launch envelope. Migrating deposits share the same deterministic sand section sampler between road geometry, contact drag and atmospheric exposure; uncovered deck preserves baseline response. Runtime identities include route geometry, jumps, flight rules and deposit behavior. Rival adapters do not register the player's local overlay.

The fossil kit retains Blender sources, real cortical apertures and source-linked sandfall assemblies. Terrain contact queries interpolate the exact rendered triangle field, so fossil skirts and station anchors use the displayed ground height. Forked road supports raycast the actual authored skull and vertebral floors first, orient their spread shoes to the receiving normal and fall back to the surveyed terrain. The Saffron runtime stores a grazer trigger epoch and consumed lap under `saffron.grazer`, carried through shared device snapshots at `frame.motion.motion.saffron`. A forward crossing 330 m before the Vista starts one event per lap; manual recovery preserves that eligibility, while fresh sessions reset it. Named ridge/breach scenarios seed deterministic poses. Presentation samples simulation time against the epoch along a fixed right-to-left world transect centred 1,050 m ahead of the authored Vista approach, with +Z shovel forward, continuous surveyed ground following, delayed body lift/dive and a buried tail.

# Verification tools

Run these commands from the app directory. `<dev-server>` means a Vite development server; a compiled preview does not serve the `/src/...` modules used by checks that import or intercept source modules. Entry, frontend, component and compatibility launcher checks cover different contracts.

`VN_URL=<dev-server> node tools/entry-verify.mjs --desktop` checks the centered manual Start screen and three real careers: Start is the only title action, tabs appear only after activation, the ship's five-second fade never auto-advances the title, and Enter/Space/controller A advance exactly once. Music remains visible and can be paused before Start. It also verifies unsupported unscoped saves stay unused, all three slots can be created, career import/cup/ghost/backup and ship/circuit choices stay isolated, switching/reload retain the active career, and Settings/Tunes work after Start before a career is chosen. Tunes expands the existing floating player over the current screen, keeps the selected page tab, and restores focus when closed. Blue Hour resets at each app launch while shared audio continues across UI navigation. Once desktop iteration is ready, run `--responsive` for native touch Start, career creation/switching and floating Tunes in portrait, landscape and narrow/tablet layouts. It writes no artifacts. Normal entry, including remembered/explicit level links, always shows Start; `?intro=0` explicitly opens the active career or picker, while developer/inspection/capture entries remain direct. Without a career those special entries use isolated memory rather than creating a saved career.

`VN_URL=<dev-server> node tools/music-startup-verify.mjs --desktop` mounts the production music player in an isolated component fixture. It checks Blue Hour startup, obsolete preference removal, callback handoff, expansion/close and focus return, playback, Pause, delayed-play cancellation, persistence/reload and simulated autoplay rejection/retry. Omitting `--desktop` adds resize/focus checks; it does not run the full transport interaction set at phone sizes or navigate the real shell. Use the entry checks and controller `--tunes` checks for shell integration, within the assigned viewport scope. It uses muted headless Chrome and leaves no artifacts.

`VN_URL=<preview-url> node tools/mobile-graphics-verify.mjs` checks fresh phone Low defaults in portrait/landscape, race startup and driving-pad input in headless WebKit. It injects `WEBGL_lose_context` during real shader creation to verify one High-to-Low retry and a recoverable Low failure. Install the Playwright WebKit browser first; set `VN_BROWSER=chrome` for a Chrome regression or `VN_CHECK=<regex>` to select cases. It writes no artifacts. Emulation does not reproduce an iPhone's hardware memory limit; physical Safari verification remains separate.

Run `npm test` for all circuits' numerical checks: magnetic handling, Nacre flight, devices, camera composition, track frames/clearance, replay, catalog loading and resource lifecycle. `npm run lint` checks source and formatting; `npm run build` produces the shared application.

Jump Drive checks live in `equipment-jump-physics.test.mjs` (tuning, sampled contacts, settling and replay), `equipment-jump-production-edges.test.mjs` (actual production skins and both road edges), `equipment-jump-landing.test.mjs` (tube surface coordinates and native landing continuity), and `equipment-jump-camera.test.mjs` (off-centre and deflected Halcyon/Orbital landing views).

Run `npm run check:level -- <slug>` for the reusable CPU module/track/racing contract (all production levels must declare shared racing) and `VN_URL=<preview-url> npm run verify:level -- <slug>` for the generic short hidden runtime smoke check. See [level-checks](level-checks/README.md) for options, scope and limitations.

`VN_URL=<server-url> node tools/controller-verify.mjs` checks controller-only Settings navigation, all driving presets against real input/physics, dead-zone calibration, keyboard adjustment, normal cameras, held-button transitions, disconnect/reconnect, saved preferences and retained Settings/Resume for each session type. It injects a synthetic standard gamepad only in the browser, with no release hooks. Run `--responsive` once desktop iteration is complete for final portrait/landscape settings checks. `--tunes` checks floating Tunes over the current setup/pause screen, transport/song/volume, View while driving, keyboard/controller focus return and frozen pause time; combine it with `--responsive` for the final layout check. `--audio` checks the three Settings audio lanes, live percentages, Master mute, bidirectional Tunes slider sync and persistence without loading a world; combine with `--responsive` for final portrait/landscape checks. `--career` checks controller access to the compact Career page’s expandable reward explanation and Back focus return. `--desktop-controls` targets a served desktop renderer build with a test-only preload stub and checks fullscreen placement, native-state synchronization and keyboard/controller access through setup, Settings, Garage and pause at desktop sizes. Pair it with the native Electron probe; it does not test OS fullscreen transitions. It writes no artifacts unless `VN_EVIDENCE` names a screenshot, and does not replace physical-device testing.

`VN_URL=<dev-server> npm run verify` is the maintained player-flow check: mode setup and selection, fleet loading/retry, countdown, retained sessions, inspection, accelerated replay finish, Continue/pause, cancellation, developer entries and responsive cinematic menus with separate pickers. It seeds an active career and adds `intro=0`; normal manual Start/career entry is covered separately by `entry-verify.mjs`. Inspector checks include cancellation and failure/retry during rival replacement, preserving the previously visible model. It launches one hidden browser and writes no captures/reports. Use `-- --desktop` while iterating and `-- --responsive` for final production layout checks; developer inspector checks remain desktop-only. `VN_CHECK=<name-regex>` selects cases. `VN_BROWSER_PATH` or `VN_BROWSER_CHANNEL` selects a browser (Chrome by default).

`VN_URL=<server-url> npm run verify:orbital` now calls the generic `verify:level` harness for Orbital. `verify:level` intentionally retains `capture=1` and the labelled developer launcher's controls; it does not certify the frontend. Results print to stdout. Set `VN_EVIDENCE=<ignored-scratch-folder>` only when a retained JSON diagnostic is needed, then remove it after diagnosis.

Run `node tools/assets-verify.mjs` for canonical runtime inventory, provenance and embedded GLB dependencies; `node tools/rival-assets-verify.mjs` also checks rival geometry and export hashes. `node tools/generate-ship-collision-hulls.mjs --check` validates model-derived contact proxies and their source identities. `landing-adhesion.test.mjs` checks the real Umbra Fold touchdown, immediate physical adhesion and steering, and bounded visual settling. `magnetic-placement.test.mjs` checks every ten-racer starting grid on all fourteen courses, countdown/reset continuity, inactive rivals and pre-start replay. `nightweir-road-smoothness.test.mjs` checks the starting bank, actual tessellated skin, three-second idle and native cruise/boost ride across all three corkscrews, including both hulls and visible-pose ripple. `nacre-road-smoothness.test.mjs` checks continuous panel joins and former support cutoffs. `colossus-umbra-road-smoothness.test.mjs` checks both reversing beds and the flush inversion deck. `glasswake-vesper-surface.test.mjs` checks full native skin coverage and corkscrew hull clearance; `zephyr-road-smoothness.test.mjs` checks the choir support boundary. `start-seams.test.mjs` checks every starting-grid and lap seam; `saffron-road-smoothness.test.mjs` covers the opening and later bank facets; `worldspire-start.test.mjs` covers its opening bank. `worldspire-road-smoothness.test.mjs` checks actual-skin native and visible-pose ripple throughout all three corkscrews with Kestrel and Shrike at cruise/boost. `magnetic-handling.test.mjs` checks boosted turn-in, unchanged yaw, airbrake/surface grip and retained shove momentum. Focused physical-contact regressions live in `racer-contacts.test.mjs`, `rapier-magnetic.test.mjs` and `rapier-flight.test.mjs`; `staged-level-runtime.test.mjs` checks shared-step ordering with local mechanics. `road-contact.test.mjs` covers the shared crest/bank catches with solo and paired query-controlled hulls; `road-surface.test.mjs` checks authored surface continuity, contact ownership and restoration.

`VN_URL=<dev-server> node tools/cup-awards-verify.mjs` checks illustrated cup selection, keyboard/controller actions, the winner reveal, reduced motion, collection persistence and settling current saved cup wins. It injects classification only at the browser boundary; it does not certify physical race completion. Default viewport is desktop; use `VN_CUP_VIEWPORT=390x844` only for final responsive verification. Optional `VN_CUP_CAPTURE` names an existing ignored temporary capture directory. `node tools/export-cup-art.mjs` rebuilds the eight runtime WebPs from the approved PNGs listed in `assets/ui/cups/provenance.json` and updates their source/hash record. Keep only the current `<cup>-trophy.png` and `<cup>-background.png` sources in that folder; Git history retains earlier iterations.

`node tools/profile-jump-physics.mjs zephyr` (or `umbra`) runs a short ten-ship CPU probe around the first jump. Optional `--jump`, `--ticks`, `--racers` and `--approach` select the section and field. It prints per-100-metre control-tick costs for AI, staging, collision movement, spatial candidates, cached-hull sweeps, proximity queries and finishing, plus launch/landing events and each racer’s landing/recovery outcome. The real chassis, shared dynamics and devices are used; the player is AI-driven for repeatability. Use `--start 0 --speed 0` to profile the opening grid/boost/waves instead of starting near takeoff, and compare `--racers 1` against `--racers 10`. `rapier-collisions.test.mjs` also guards against rebuilding native convex meshes during movement/contact retries. Output stays on stdout. These timings isolate simulation work and do not measure renderer/GPU cost or foreground FPS.

After a ship source/export changes, run `blender --background --python tools/extract-ship-collision-assemblies.py`, then `node tools/generate-ship-collision-hulls.mjs`. Generation conservatively simplifies structural hulls with a measured 10 mm maximum excess and exact assembly bounds. `node --test tools/ship-collision-hulls.test.mjs` verifies that bound, compound surface coverage, open-frame recesses and replay identities without needing Blender. See the [ship source workflow](../src/ships/README.md) for the intermediate geometry contract.

Use the maintained entry/frontend harnesses for player flows and the generic level smoke harness for the runtime contract. Authored CPU tests retain course physics, replay, camera and asset-ownership assertions. Browser smoke checks sample ordinary driving and failure cleanup; they do not exercise every authored jump, course-specific asset failure or mobile HUD layout. Add browser regressions to these maintained harnesses when needed. The obsolete standalone shell, fleet, circuit and expansion browser drivers have been retired.

Use `VN_URL` to target the intended existing server, respecting each command’s dev/build requirements. Verify the served revision before opening a browser. Keep checks hidden/headless and use short real-input segments plus fast numerical traversal/replay checks. Run normal-speed automated full laps only when the user explicitly requests them. No unsolicited videos or reference playback.

For tools that support explicit diagnostics, `VN_EVIDENCE` selects ignored output. Raw captures/reports belong in `.experiments/` and should be removed at the end of the pass. Preserve servers owned by other sessions and close the verification browser afterward. Hidden timings and viewport checks do not establish foreground performance, physical-device support or audible quality.

`node tools/expansion-zephyr-clearance.mjs` samples exported triangles around the banked route and flight poses. This CPU geometry probe does not cover the frontend.

`VN_URL=<dev-server> node tools/time-trial-verify.mjs` checks the Time Trial entry, continuous real-physics driving beyond three laps, immediate standing/flying ghosts, deterministic retry, filterable records, stored best after reload and return to Practice. Set `VN_TRIAL_LEVEL=shatterline` for the one-descent equivalent. A browser-only response override provides accelerated stepping; production has no finish shortcut. It uses hidden Chrome and writes no artifacts. After desktop iteration, `VN_TRIAL_VIEWPORT=390x844` or `844x390` also checks touch launch, retry, boost/release and pause retry; these are final mobile/portrait checks. `src/race/time-trial.test.js` covers timing, validity, ghost compatibility, storage failure and disabled road devices.

`VN_URL=<dev-server> node tools/cup-verify.mjs` checks a complete Founders Cup (`VN_CUP_ID=frontier`, `horizon` or `apex` selects another cup) with accelerated real physics, locked ship/difficulty, saved result and unfinished-race reloads, retry during unfinished cups (including sprint/circuit transitions), format-aware placement points, cumulative/final standings, automatic completion cleanup, restart and abandon. Browser-only response instrumentation supplies stepping up to the player finish, then the production fast-forward resolves the field. It checks the finish banner clock, pause/hub suspension and direct transition to scored standings; production has no finish shortcut. `src/core/cup-finish.test.js` compares fast-forwarded rival times and classification with ordinary fixed ticks, including invalid finishes and DNFs, and guards the full simulated deadline and per-frame work budget. It uses hidden Chrome and writes no artifacts. Run `VN_CUP_VIEWPORT=390x844` or `844x390` only after desktop iteration for the final touch/portrait flow, including boost/release, pause retry and cup-width overflow checks. `src/race/cup.test.js` covers scoring, tie-breaks, save validation and storage failures.

`VN_URL=<dev-server> node tools/cup-ui-verify.mjs` uses browser-only result fixtures to verify keyboard cup selection, Settings focus return, stable waiting-panel identity, nearby and final standings, reduced-motion track highlights, keyboard cancellation/confirmation and saved cup identity. Set `VN_CUP_ID=frontier`, `horizon` or `apex` to start with another cup. After desktop iteration, `VN_CUP_VIEWPORT=390x844` or `844x390` checks the same results flow at touch viewport sizes. It does not certify physical race completion; use the full cup check for that. `src/frontend/cup.test.js` covers the front/back edges of the nearby standings, invalid finishes and visible storage failures. `--session-return` focuses on Settings resume visibility for unfinished cups, completed-cup cleanup and retained non-cup sessions; `VN_CUP_VIEWPORT` selects the viewport.

`node tools/demo-rewards-verify.mjs` (after `npm run build:demo`) checks the four demo milestones through short browser-only finish gates, keyboard/controller equipment selection, the four-notch unlock bar, final responsive layouts and the compiled renderer’s edition/dev boundaries. The compiled-renderer check imports a full career through the save UI and verifies that the demo still shows four collected rewards after reload while preserving all 28 saved claims. `node --test tools/demo-rewards.test.mjs` covers bidirectional save transfer, edition limits and Demo Cup scoring.

`VN_URL=<dev-server> node tools/progression-verify.mjs` checks compact hero/loading reward badges, all 28 generated icon exports, hover/keyboard/controller reward-detail dismissal, valid fourth-place progression through the first equipment unlock, reward claims/retries, a seeded final cup event, two distinct stock Time Trial records, all six abilities through keyboard/controller input, additive road pickups, persistent Race/Garage tabs, the dev=1/2 Ship inspector shortcut with AI racers and sound/effect auditions, undiscovered-item hiding in fresh/partial saves and the inspector, two/four-item capacity, cup hull locking, four keyboard/controller inputs, garage focus return, permanent Quad Core confirmation, save transfer and inspector stat alignment. It uses isolated `dev=1/2` profiles and the browser-only near-finish gate (`?dev=1&finish=1&place=4` finishes fourth; `place=1` is the default); it does not drive full cups. `VN_CHECK=<regex>` selects cases; `--responsive` runs the final production garage and touch equipment checks. Developer-only inspector VFX/Sounds auditions are desktop-only; skip mobile/portrait checks for `dev=1`/`dev=2` tools. Numerical progression/equipment tests cover claim idempotence, player-only tuning, independent slots, cooldowns, shields, Jump landing, toughness and import rollback. Desktop build audits reject the developer modules and unlock/setup entry points.

`VN_URL=<dev-server> node tools/capture-ship-previews.mjs` refreshes the four fleet-rail JPEGs in `public/assets/menu/ships/` from the production studio, at 400×225. It uses one hidden renderer and writes the captures after rendering all hulls so Vite reloads cannot interrupt capture. These are menu thumbnails; no ship model or material changes are made.

The marketing tools record only when explicitly requested. `node tools/marketing/trial-capture.mjs --record --output <new-directory>` drives a genuine standing warm-up and a full-pace flying lap in an isolated career, then continues into the next lap to reveal the saved flying ghost. It saves native footage, the four-second line-crossing excerpt marker and `trial-fixture.json`. Omitting `--record` rehearses headless; each run needs a fresh output directory. `node tools/marketing/menu-capture.mjs --record-fixture <fixture.json> --output <new-directory>` captures the real title and three menu chunks, including a capture-only standard cursor tied to actual pointer events. `--flow-only` rehearses without recording, and `--only intro,menu-circuits,menu-garage` selects sources. Run actual captures sequentially so tabs do not compete for focus/performance. Use the [working trailer script](../marketing/script.md) and edit plan; `prototype.mjs --assemble-only --shots marketing/edit-plan.json --output <conformed-source-directory>` assembles an existing manifest. Gameplay capture plans can set `captureDeviceScaleFactor` (default 1) and `captureMimeType` (VP9/Opus by default, or VP8/Opus); the manifest retains the actual rendering scale and codec. Edit plans select a registered music track and can set `crf` (default17), `music.leadIn`, and ordered `music.phraseJumps` for musical conformance. `assembleTrailer` accepts `copyVideoFrom` to remix audio while copying an existing H.264 stream without re-encoding picture. Raw sources stay under ignored `.experiments/`; the approved Blue Hour movie and its saved script/edit plan live under `marketing/rc3/`.

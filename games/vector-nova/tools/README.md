# Verification tools

`VN_URL=<preview-url> node tools/mobile-graphics-verify.mjs` checks fresh phone Low defaults in portrait/landscape, race startup and driving-pad input in headless WebKit. It injects `WEBGL_lose_context` during real shader creation to verify one High-to-Low retry and a recoverable Low failure. Install the Playwright WebKit browser first; set `VN_BROWSER=chrome` for a Chrome regression or `VN_CHECK=<regex>` to select cases. It writes no artifacts. Emulation does not reproduce an iPhone's hardware memory limit; physical Safari verification remains separate.

Run `npm test` for all circuits' numerical checks: magnetic handling, Nacre flight, devices, camera composition, track frames/clearance, replay, catalog loading and resource lifecycle. `npm run lint` checks source and formatting; `npm run build` produces the shared application.

Run `npm run check:level -- <slug>` for the reusable CPU module/track/racing contract (all production levels must declare shared racing) and `VN_URL=<preview-url> npm run verify:level -- <slug>` for the generic short hidden runtime smoke check. See [level-checks](level-checks/README.md) for options, scope and limitations.

`VN_URL=<server-url> npm run verify` is the maintained player-flow check: mode setup and selection, fleet loading/retry, countdown, retained sessions, inspection, accelerated replay finish, Continue/pause, cancellation, developer entries and responsive cinematic menus with separate pickers. It launches one hidden browser and writes no captures/reports. Use `-- --desktop` while iterating and `-- --responsive` once desktop work is final; `VN_CHECK=<name-regex>` reruns a specific failing case. `VN_BROWSER_PATH` or `VN_BROWSER_CHANNEL` selects a browser (Chrome by default).

`VN_URL=<server-url> npm run verify:orbital` now calls the generic `verify:level` harness for Orbital. `verify:level` intentionally retains `capture=1` and the labelled developer launcher's controls; it does not certify the frontend. Results print to stdout. Set `VN_EVIDENCE=<ignored-scratch-folder>` only when a retained JSON diagnostic is needed, then remove it after diagnosis.

Run `node tools/assets-verify.mjs` for canonical runtime inventory, provenance and embedded GLB dependencies; `node tools/rival-assets-verify.mjs` also checks rival geometry and export hashes. `node tools/generate-ship-collision-hulls.mjs --check` validates model-derived contact proxies and their source identities. `landing-adhesion.test.mjs` checks the real Umbra Fold touchdown, immediate physical adhesion and steering, and bounded visual settling. `magnetic-placement.test.mjs` checks countdown/reset continuity, inactive rivals and pre-start replay on several real roads. `magnetic-handling.test.mjs` checks boosted turn-in, unchanged yaw, airbrake/surface grip and retained shove momentum. Focused physical-contact regressions live in `racer-contacts.test.mjs`, `rapier-magnetic.test.mjs` and `rapier-flight.test.mjs`; `staged-level-runtime.test.mjs` checks shared-step ordering with local mechanics. `road-contact.test.mjs` covers the shared crest/bank catches with solo and paired query-controlled hulls; `road-surface.test.mjs` checks authored surface continuity, contact ownership and restoration.

`node tools/profile-jump-physics.mjs zephyr` (or `umbra`) runs a short ten-ship CPU probe around the first jump. Optional `--jump`, `--ticks`, `--racers` and `--approach` select the section and field. It prints per-100-metre control-tick costs for AI, staging, collision movement, spatial candidates, cached-hull sweeps, proximity queries and finishing, plus launch/landing events and each racer’s landing/recovery outcome. The real chassis, shared dynamics and devices are used; the player is AI-driven for repeatability. Use `--start 0 --speed 0` to profile the opening grid/boost/waves instead of starting near takeoff, and compare `--racers 1` against `--racers 10`. `rapier-collisions.test.mjs` also guards against rebuilding native convex meshes during movement/contact retries. Output stays on stdout. These timings isolate simulation work and do not measure renderer/GPU cost or foreground FPS.

After a ship source/export changes, run `blender --background --python tools/extract-ship-collision-assemblies.py`, then `node tools/generate-ship-collision-hulls.mjs`. Generation conservatively simplifies structural hulls with a measured 10 mm maximum excess and exact assembly bounds. `node --test tools/ship-collision-hulls.test.mjs` verifies that bound, compound surface coverage, open-frame recesses and replay identities without needing Blender. See the [ship source workflow](../src/ships/README.md) for the intermediate geometry contract.

The older `verify.mjs`, `orbital-verify.mjs`, fleet/rival, racing, Halcyon/Nacre and Gate browser harnesses are **historical and not certified against the current frontend/session lifecycle**. They retain useful detailed physics/scenario assertions, but some assume automatic world boot, old DOM selectors or old results behavior. Do not run them as the current acceptance suite or simply add `capture=1` and assume all their assertions are current. Migration/retirement is tracked in the roadmap; no level contract APIs were removed. Level-specific expansion tools remain available for their authored scenarios—inspect their launch assumptions and the assigned campaign's viewport scope before use. CPU tests and the generic level smoke harness remain the supported level-contract checks.

Use `VN_URL` to target the intended existing preview. Verify the served build before opening a browser. Keep checks hidden/headless and use short real-input segments plus fast numerical traversal/replay checks. `lap-run.mjs` is a legacy real-time full-lap driver; run it only when the user explicitly requests that check. No unsolicited videos or reference playback.

For tools that support explicit diagnostics, `VN_EVIDENCE` selects ignored output. Raw captures/reports belong in `.experiments/` and should be removed at the end of the pass. Preserve servers owned by other sessions and close the verification browser afterward. Hidden timings and viewport checks do not establish foreground performance, physical-device support or audible quality.

`VN_URL=<preview-url> node tools/expansion-zephyr-verify.mjs` checks short real-key cathedral traversal, waterfall flights, recovery, tower pause/replay and owned geometry/sky load failures; `--shape` selects the neutral route. `node tools/expansion-zephyr-clearance.mjs` samples actual exported triangles around the banked route and flight poses. After desktop critique, `VN_URL=<preview-url> node tools/expansion-zephyr-mobile.mjs` checks full-hull framing, HUD/touch separation, release/cancel/blur and recovery in portrait and two landscape sizes at high/low/reduced motion; `VN_SHAPE_ONLY=1` selects shape review, and `VN_VIEWPORT=portrait,landscape,compact` can select affected sizes for a recheck.

`VN_URL=<dev-server> node tools/time-trial-verify.mjs` checks the Time Trial entry, continuous real-physics driving beyond three laps, immediate standing/flying ghosts, deterministic retry, filterable records, stored best after reload and return to Practice. Set `VN_TRIAL_LEVEL=shatterline` for the one-descent equivalent. A browser-only response override provides accelerated stepping; production has no finish shortcut. It uses hidden Chrome and writes no artifacts. After desktop iteration, `VN_TRIAL_VIEWPORT=390x844` or `844x390` also checks touch launch, retry, boost/release and pause retry; these are final mobile/portrait checks. `src/race/time-trial.test.js` covers timing, validity, ghost compatibility, storage failure and disabled road devices.

`VN_URL=<dev-server> node tools/cup-verify.mjs` checks a complete Founders Cup (`VN_CUP_ID=frontier`, `horizon` or `apex` selects another cup) with accelerated real physics, locked ship/difficulty, saved result and unfinished-race reloads, retry at every later event (including sprint/circuit transitions and the fourth Apex event), format-aware placement points, cumulative/final standings, restart and abandon. Browser-only response instrumentation supplies stepping; production has no finish shortcut. It uses hidden Chrome and writes no artifacts. Run `VN_CUP_VIEWPORT=390x844` or `844x390` only after desktop iteration for the final touch/portrait flow, including boost/release, pause retry and cup-width overflow checks. `src/race/cup.test.js` covers scoring, tie-breaks, save validation and storage failures.

`VN_URL=<dev-server> node tools/cup-ui-verify.mjs` uses browser-only result fixtures to verify keyboard cup selection, Settings focus return, live/final classification focus, saved cup identity and confirmed switching between cups. Set `VN_CUP_ID=frontier`, `horizon` or `apex` to start with another cup. It does not certify physical race completion; use the full cup check for that.

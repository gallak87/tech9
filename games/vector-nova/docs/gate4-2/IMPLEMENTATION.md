## Implemented simulation contract

`runtime.js` is the pure Halcyon adapter; `index.js` attaches owned browser presentation. Runtime identity is `halcyon-pickups`, version 2, rules `halcyon-immediate-v1-142-50-1.25-6-layout1`. The no-feature magnetic identity remains unchanged. Core changes in this lane come only from the reviewed Gate 4.1 preflight and repair patches recorded in STATUS.json and INTEGRATION.md.

Each 120 Hz step expires timers (remaining <= dt expires before physics), cancels Vector on brake >= 0.1, supplies current modifiers to shared physics, consumes a shield only on a qualifying protected impact, then sweeps ordered forward device crossings and activates for the next step. On one tick, expiry precedes impact; impact precedes new pickup. Thus a newly collected shield cannot protect an earlier same-tick collision. A consumed shield can be replaced by a different pickup crossed later on that tick. No stacking or duration extension occurs while the same effect is active. Paused/hidden frames advance no effect time.

Sweeps use unwrapped centre-plane crossings, interpolated lateral position and yaw-dependent hull extent. A first forward pass spends that device occurrence even for a lateral miss, braking pass or unavailable active effect. Reverse travel, standing and oscillation cannot rearm it. The ledger rearms on a genuine next forward unwrapped traversal; fresh-lap/scenario restart deliberately resets it. Manual recovery preserves the passed-device ledger and high-water distance while clearing effects and presentation.

The protected rail impact skips only its 6 + severity × 9 reserve deduction inside collision resolution. Position separation, reflected lateral velocity, 0.84 speed multiplier and heading reduction remain identical. The next qualifying contact is unprotected. Ordinary regeneration and manual boost spending remain active.

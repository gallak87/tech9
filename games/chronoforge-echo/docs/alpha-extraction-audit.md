# RGB atlas extraction repair — 2026-09-16

The user's screenshots exposed a real defect missed by the earlier coarse scene review. Several generated sources contain an opaque white/gray checker pattern in RGB pixels. Clearing only the connected exterior left checker islands inside hair loops, bent arms, capes, raised hands, and between legs and weapons. Pink/gold glow also tinted some background pixels beyond the old neutral-color threshold, leaving jagged pale blocks in action poses. This was an import defect, not transparent PNG content.

The repair is in `src/assets.js`, `src/alpha-masks.js`, and two extra measured Vex gait seeds in `src/hero-walk-frames.js`. The importer still floods from the exterior and explicitly measured background points. Local source-coordinate zones relax the color predicate only around identified luminous effects/cape gaps; they do not turn every pale pixel transparent. Dark and saturated boundaries keep costume, armor and physical weapon cores opaque. No source PNG, body proportions, face, crop, foot anchor or display scale was modified for this repair.

`evidence/alpha-source-audit.json` records the eleven exact input sizes, color modes and SHA-256 hashes. The original generation prompts remain in `docs/asset-prompts.json`, `docs/companion-walk-prompts.json`, and the existing asset provenance files. The new world-interaction sheet was produced separately by the world-art owner: `public/assets/world-props-prompt.json`. It has genuine RGBA transparency and enters the manifest without a color key. The new `worldProp` manifest case calls `installWorldPropAtlas(image, metadata)`.

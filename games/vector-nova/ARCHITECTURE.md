# VECTOR//NOVA architecture

## Stack and module boundaries

Standalone Vite + Three.js ES modules, WebGL2, PBR/ACES and sRGB output. No repository framework, alternate launcher or cloned runtime. See the [README](README.md) for available circuits and the [roadmap](ROADMAP.md) for planned work.

The locally owned ESLint/Prettier/lint-staged/Husky configuration was adapted from Chronoforge Echo at the user's request.

| Module                 | Responsibility                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| levels                 | Validated discovery, per-level factories, metadata and presentation adapters              |
| core                   | Boot/readiness, fixed-step session, replay, mode changes and teardown                     |
| track                  | Optional route-frame, sweep and geometry mechanics                                        |
| environment / renderer | Optional placement mechanics; shared rendering, lighting and resource metrics             |
| ships / camera         | Selectable async fleet assets and local presentation; road-frame chase/inspection cameras |
| physics / race         | Vehicle motion and rail response; checkpoint/lap validation                               |
| input / ui             | Normalized controls, focus/visibility cleanup, menus/HUD/settings                         |
| audio / effects        | Event-driven presentation; failure must not stop simulation                               |
| pickups                | Shared automatic devices and owned visual/audio presentation                              |

`src/levels/<slug>/track/`, `environment/` and `backdrop/` own each circuit’s route, construction, materials, scenery and sky; Nacre also owns its overlay and flight presentation adapter. Shared directories contain reusable mechanics, never a default world style. Asset URLs follow stable level/ship folders; replay identities are independent of asset filenames.

`src/levels/` discovers asset-free metadata eagerly and imports only the selected implementation. Its [level API](docs/LEVEL_API.md) defines factories, presentation and ownership; unknown or malformed levels fail visibly.

The shell serializes cancellation, disposal and world creation. Phase checkpoints yield between route/graphics/world/ship/warmup tasks and surface errors with retry/back. ### Circuit preview refresh

Circuit thumbnails are saved **640×400 WebP captures of the real pulled-back free camera at Low quality**. They are runtime assets, not live views or verification evidence. The capture hides racers/effects, backs away from the grid, lifts the camera and aims toward the route centre. Hover only switches the saved image. `tools/menu-catalog.mjs` generates SVG outlines/facts from CPU route models; it never imports world factories or recursively scans/hashes source or asset trees.

Saved images remain visible across source changes. A genuinely missing file falls back to the route outline with a developer warning; malformed WebPs, incorrect dimensions or invalid manifest paths fail the build. Route-signature/preset differences are **advisory** warnings, never visibility gates. They cannot detect scenery, lighting or borrowed-asset changes: explicit refresh remains the author’s responsibility.

After final visual changes, from this app directory:

1. Use Node 22 and an existing dev server, or start one on a free port: `npm run dev -- --port 5197`. Preserve servers owned by other sessions.
2. Refresh named circuits explicitly: `VN_URL=http://127.0.0.1:5197 npm run previews -- halcyon nacre`. Named circuits are always recaptured. No IDs refreshes all circuits; `--missing` only fills missing stills. The old `--force` spelling remains accepted.
3. Refresh consumers of borrowed/shared art too. Shared visual changes need an all-circuit refresh. Unrelated code or formatting changes do not require recapture.
4. Inspect the changed images, build, and commit each WebP with `public/assets/menu/previews.json`. Close your own server/browser. Do not keep parallel captures, reports or audit JSON.

The version-1 manifest records each filename, dimensions, capture preset, source revision/dirty flag and CPU route signature. Migrated images retain their old fingerprint as provenance with `sourceRevision: null` because the original exact revision was not recorded; no new capture is implied. The tool updates each record immediately after its image is saved. Source revision is provenance, not an automatic freshness test. Capture uses `?level=<id>&capture=1&music=0`; the compatibility launcher is intentional here. The shipped stills and user-requested art concepts remain registered in [the asset manifest](docs/ASSET_MANIFEST.json).

The mode picker selects setup without starting a session. Championships opens the shared cup hub; switching modes preserves saved cup scores. Result retry restarts the same session, and Back to setup retains its mode, track and ship. The retained-session action names its original mode even while another mode is being configured. `src/frontend/records.js` browses validated local Time Trial bests, with track and ship filters and a setup shortcut. `readTrialRecords()` keeps exact identity profiles separate and reports durable time/ghost storage independently of session memory. The lightweight menu catalog includes the physics track ID for matching saved identities without loading a world; full best/ghost compatibility remains a race-start check.

## Menu input contract

Every player-facing menu change includes keyboard and standard-controller access. Use native `button`, `select`, checkbox and range controls with accessible names. Route activation through existing actions/click handlers, keep DOM order intentional, respect disabled/hidden/inert controls, and provide visible focus. Use `tabindex="-1"` only for nonsequential or managed roving focus, never as the sole route to a new action.

`src/input/menu-gamepad.js` discovers visible enabled controls in the frontend, inspector, pause and active Tunes roots. A activates the focused control; B and Menu/Start use the existing Escape path. D-pad/left stick navigation delegates to existing button arrow handlers, then falls back to DOM focus order. Left/right adjusts native selects/ranges; A toggles checkboxes. Ordinary new buttons need no per-button controller mapping. Preserve existing spatial/roving keyboard handlers when extending grids and lists; custom widgets need equivalent shared keyboard behavior, and new overlay roots must join `menuRoot()` so focus cannot escape to a covered menu. Consume handled events with `preventDefault()` to avoid a second race action after returning from a menu.

Tunes opens from setup or pause with focus on Play/Pause; B/Escape closes it and restores the invoking button without resuming the race. Its active root owns controller navigation and Tab focus. View/Select toggles music independently of the driving preset. Range adjustment must dispatch both input and change so audio sliders and saved settings share the same controller path. Steam builds omit the in-race shortcut footer; bindings remain in Settings. Browser hints are unchanged.

Settings can open from setup or pause. Back restores its originating screen/focus; the gold retained-session action is present for Quick Race, Practice, Time Trial and cups, returning to the existing paused scene before simulation resumes. Never restart or advance a session while editing settings. Controller presets/dead zone live in the shared settings store, update hints immediately and persist locally. The steering test reserves the left stick while focus is inside controller settings; D-pad still navigates/adjusts. This prevents calibration from editing itself. Racing uses the selected layout, a 0–40% dead zone (15% default) and unchanged steering assistance. Menu stick navigation keeps its independent 55% threshold. X cycles normal cameras; recovery has no controller binding. Held buttons must be released after context changes/reconnect, and unplugging during play pauses.

For each menu change, verify reachability/activation/back and focus return with keyboard and synthetic controller input, including focused selects/sliders and any retained race. Extend `tools/controller-verify.mjs` or the maintained frontend verifier for new behavior; do not add release test hooks. Run the affected hidden desktop checks first and relevant responsive checks once implementation is final. Physical controller/Steam Input validation remains separate.

## Route, coordinates and handling

`src/input/touch.js` supplies two independently captured pointer controls to the shared input sampler: left/right analog steering with a downward airbrake zone, and a right-hand Boost/Go/Neutral/Brake rail. Boost also holds throttle. Each pad retains one pointer through out-of-bounds drags; release/cancel/lost capture resets only that pad. Input clear, pause, suspension, focus loss and viewport resize reset both pads and their indicators. Touch feeds the existing normalized input and physics; keyboard and gamepad mappings remain unchanged. Narrow, short-landscape and coarse-pointer viewports expose the pads, with telemetry kept clear of them.

- Metres/seconds/radians. World +Y up; ship local +Z forward, +Y up.
- `sample(distance)` wraps arc-length metres and returns `{position, tangent, right, up, quaternion, curvature, bank}`, optionally `roll`. Road, ship, camera and physics consume the same frame.
- The legacy `frame.right` is geometric +X, which appears driver-left when facing +Z. Positive input steer means driver-right: negative geometric heading/lateral displacement. Do not reverse this when adding levels.
- Reuse `src/track/frames.js` for continuous parallel-transport frames through vertical tangents/inversions and lap closure. Reconstructing every frame from world-up crossed with tangent fails at vertical directions. The optional [geometry helpers](src/track/README.md) retain authored profiles and local clearance rules; no shared world preset is applied.
- Track models expose unique/versioned identity, length, full width, ordered checkpoints, contiguous named sections, scenarios and bounds. Production and shape views share one route.
- Fixed simulation is 120 Hz, capped at 0.1 s / 12 catch-up steps. Pause/visibility loss clears the accumulator. Render interpolates distance and quaternion; presentation never mutates simulation.
- Bend assistance is 0.3. Persistent heading retains the unassisted yaw, while a separate steering response preserves manual turn-in. Pitch/roll adhere to the magnetic surface.
- Gravity projects through tangent/right axes; an explicit neutral-input parking hold prevents slope/bank creep. Production racers use physical hull/rail contacts; manual recovery resets that actor and invalidates the lap.

Shatterline retains stable authored source addresses while its physical road folds back beneath earlier reaches. `distanceAt`/`sourceAt` convert source addresses and race arc length; `pointAtSource` returns actual world position. `spineZAt`/`sourceAtSpineZ` describe only the monotone scenery reference spine. Their compatibility aliases `worldZAt`/`sourceAtWorldZ` are not inverses of physical road Z. Placement near crossings must use actual three-dimensional road positions and branch clearance, with `nearestSourceAt` available for spatial ownership.

Shatterline opts into a course-owned pace profile shared by grounded motion and rival speed selection. Per-ship cruise and boost targets scale independently; lower excess-speed resistance carries earned descent and landing momentum while throttle-off drag and ordinary brakes remain effective. The profile joins runtime identity. Omitted or neutral profiles preserve the approved physics arithmetic of existing courses.

Overturn weaves through two transparent, freely drivable 70 m tubes with opposing physical bends, separated by a steeper exposed corkscrew. `track.tubes` describes each opening and closed span, `tubeAt`/`tubeProfile` select by distance, and one `tubeMesh` supplies exact shared facets for rendering, collision and hull support. The level-local surface sampler covers the entire district, including its exposed rolls, while neighboring jumps keep their world positions. Shared physics integrates surface metrics and tangent-plane gravity; periodic lateral coordinates cover each complete interior. Camera, grounded poses and contact effects use the same sampled surface. Red exit inlays begin 100 m before each opening and converge through its collector onto the road. Production rim contacts use the actual authored geometry and the same physical yaw recovery as other roads. The legacy coordinate solver retains its opt-in exit assistance for standalone route checks.

Halcyon uses a 5 km route with distributed rise/descent, full roll/inverted hold and plunge. Asterion uses 4.5 km with a wall ride, raised crossing and steep dive. Authored dimensions and section data belong in their models, not duplicated documentation tables.

## Session, devices and replay

`src/core/session-runtime.js` provides the ordinary magnetic adapter and one `advanceSession` path shared by live input and replay. The [session adapter contract](docs/LEVEL_API.md#session-adapters-and-replay) defines hooks and event order. Preserve identity `{id, version, rulesId}`; replay also checks app/track/physics versions, seed and deterministic initial state. Reject incompatible or incomplete logs.

Production descriptors declare `racing: { createDevices, createMotion? }`. Core wraps the player's existing motion adapter with `src/pickups/runtime.js`, and creates each opponent with that circuit's pure motion factory and the same device layout. `src/race/roster.js` declares nine rivals and the shared field/grid/colors; `src/race/racers.js` owns their independent vehicle/race/device states and deterministic steering, braking, manual boost and lane decisions. Rook, Latch, Mule, Pike, Tern, Manta, Vise, Kite and Gannet borrow the fleet's versioned handling profiles while rendering distinct GLBs. All ten clocks start together on a two-column, five-row grid with 12 m row spacing; rear-row travel to the start counts toward time without crediting a partial lap. Easy leaves more cornering margin and conserves reserve; Medium carries more speed and boosts more often; Hard targets a close race against clean, boosted driving. Every difficulty receives the player's full Vector propulsion and preserves earned speed instead of braking back to its preferred cruise pace. Braking handles corners, traffic and required-jump launch speeds. Manual boost uses each rival's own reserve independently of player inputs; difficulty never changes vehicle or device physics. Difficulty is fixed for the run. The pause menu can save a new difficulty for Restart Race/Restart Sprint; Resume keeps the current run unchanged. Solo practice and verification scenarios disable opponents and hide the pause difficulty picker.

All thirteen production circuits and sprints use this shared system. Nacre retains its approved version-5 landing solver inside the shared device wrapper. New circuits must declare the shared racing capability rather than implement independent devices, AI, countdown, HUD or results. Opponents render their actual interpolated flight pose and use their own reserve to reach required-jump launch speed; optional branches remain route choices. CPU adapters never own the player's local presentation ledger.

Human launches use the shared HTML/CSS start lights and three countdown beeps followed by a longer kickoff tone. `src/core/start-countdown.js` uses a pausable wall clock, armed after the first driving frame renders. Audio unlock is independent: Safari can leave `AudioContext.resume()` pending after a long load, so blocked sound never holds the countdown. Driving pointer/key gestures retry suspended audio even when an earlier resume is pending. Late frames cannot skip lights; each newly presented beat gets a full second. Vehicles, lap clocks and replay recording remain frozen until lights out. Held throttle and Shift survive the countdown-to-green transition; boost engages when the existing speed/reserve requirements are met. Input still clears on pause, suspension and focus loss. The internal verification restart/scenario API bypasses the countdown.

Competitive runs latch each racer's first two checkpoint-complete laps and classify valid finishes by total time; invalid runs remain explicitly unranked. Practice never acquires a competitive finish flag. Three red start lights turn green on GO. `src/race/finish-marker.js` places a small shared checker mesh at checkpoint zero (or an open route's `finishDistance`), conforming to road banking; optional `racing.finishMarker` paint dimensions/tones remain level-local. Completion events pass through the shared tick's event stream to a distinct finish cue and headline. A 2.4-second track-visible finish beat brakes the player and gently widens grounded chase (no camera move in reduced motion), then fades in a compact track-backed results panel. Rivals retain independent clocks until they actually finish. Continue Driving preserves the recorded result; Pause can reopen Results, and recovery does not reopen it automatically. Audio keeps finish tails audible while stopping propulsion/environment in results. Replay records competitive/solo mode and difficulty and advances rivals through the same fixed ticks; rejected initialization restores the prior field and presentation flags.

The driving HUD shows position, lap count, personal current/last/best lap times and all ten racers in race order. Mid-screen gameplay callouts and the section-name readout have been removed across all circuits: do not add jump approach, landing/recovery, surface/hazard commentary or lap-result toast components. Countdown/results, device/heat gauges and non-text environmental effects remain. Relative gaps use YOU as 0.0s, negative for rivals ahead and positive for rivals behind. `src/race/relative-timing.js` retains bounded passage samples on unwrapped course distance, interpolating the leader's passage at the trailing ship's current point; gaps never subtract lap clocks or divide distance by current speed. Recovery/reversal clears that ship's passage history, unavailable gaps remain unknown, and replay rollback includes the samples. Recorded lap/total finish times appear in the paddock. Rival minimap dots and row strips share one stable color per identity; the player has an orange marker with a white outline.

Open courses opt in with `track.closed === false`; `finishDistance` is the final checkpoint and `length` includes safe runout. The race latches one grounded ordered finish, then supplies ordinary braking controls while each unfinished rival continues independently. Sprint HUD, open minimap markers and solo results reuse shared UI. Airborne presentation progress follows the real pose within its jump corridor and never grants checkpoints. Sprint identities include format, finish and geometry; field rollback retains validated transfer keys. See the [level API](docs/LEVEL_API.md#track-and-review-contract).

Vector strips apply a +65 m/s entry impulse at leading hull contact, capped at their 600 km/h target, and add strong propulsion only while the hull overlaps the strip. The per-call road profile can exceed the selected ship's manual boost; holding boost selects the stronger active profile and still spends reserve. Exiting removes the force immediately and retains actual vehicle speed; no timed boost or reserve charge remains. Sweeps include yaw, lateral entry and lap seams. Device ticks expire Aegis's six-second protection and apply brake cancellation before physics, consume shields on qualifying impacts, then sweep new contacts. A shield collected later in a tick cannot protect an earlier impact. Effects do not stack; manual recovery clears effects while retaining the consumed-device ledger. Reverse/parking/reset farming must not rearm devices. Shields protect reserve loss, not collision separation or speed consequences. Shared rules, geometry, presentation and audio live in `src/pickups/`; placement plans live in each circuit's `devices.js`. Vector chevrons are pixel-filtered paint on the opaque casing, avoiding subpixel sliver geometry without extra textures or draws. Every road declares its rendered running skins with `mesh.userData.roadSurface` and metre-based `roadCoord` attributes. Shared pickup presentation measures those triangles to seat casings above the panel envelope; levels supply geometry only, with no mounting callbacks or per-level offsets. Missing surface declarations fail loading instead of silently falling back. Ground devices do not trigger in flight/recovery. The motion adapter receives per-tick propulsion/shield modifiers; Aegis protects rail-edge reserve loss without changing airborne deflection or landing geometry.

Every production circuit and sprint has Vector, Aegis, Repulsor, Arc and Ion in its local device list. Offensive gates occupy optional side lanes on grounded racing sections; shield choices provide counterplay. Existing launch assistance remains intact. Placements leave room after landing recovery and before takeoff, and separate Ion from the next weapon by its active duration at Vector speed. Longer sprints distribute combat over their grounded shelves and descents rather than populating every jump approach. Every racer can collect each combat gate independently once per lap, using the same personal traversal ledger as Aegis. A shared `src/pickups/combat.js` service processes crossings deterministically and advances once after every racer's completed physics tick. Combat rules/snapshots use version 3. Repulsor charges for 0.5 s before a bounded 36 m radial shove. Arc fires three pulses at 0.15, 0.60 and 1.05 s, traveling at 345 m/s plus the source ship's forward speed. Each pulse acquires the nearest visible grounded racer ahead within 220 m and a ±30° firing cone (stable identity breaks ties). Road-local homing turns at most 0.9 rad/s; losing or passing the target drops that bolt's lock without reacquiring. Hills and banks follow the road frame, and swept hull/cover contacts remain authoritative. They expire after 0.8 s, at road edges or on static collision geometry. Ion emits for 4.5 s and leaves a 3.2 s trail, with at most one hit per racer per burst. Aegis blocks both offensive impulse and reserve cost; ordinary physical collisions keep their existing rules. A shared hit grace period prevents overlapping attacks from compounding immediately. Rival lane choices consider nearby traffic and visible wakes; player controls and steering assistance stay unchanged.

The player's device runtime owns the combat replay snapshot; rivals register their own state, pose and shield/impulse callbacks. `advanceSession` resolves interactions after all staged racers finish. `createMagneticRuntime.applyImpulse(state, vector)` updates the physical actor and its speed cache together. `dynamics.occlusionFraction(start, end)` performs a static-only query and excludes racer proxies. Recovery removes that racer's active attacks; restart and Time Trial mode changes clear all combat state. Hardware, shaped charging fields, traveling pulses and lingering trails use the existing device presentation lifecycle. The shared color palette lives in `src/pickups/theme.js`; `signal.js` adds one road-projected soft edge-light draw per device and a short device-specific ship collection signature. The compact device readout projects above the rendered hull using the current camera matrix, critically damps its screen-space anchor to suppress road/camera jitter, then clamps to viewport bounds and stacks only active/recent effects. First appearance, reset, camera cuts and viewport changes snap to the new anchor; hidden readouts discard their smoothing state. Vector has untimed chevrons, Aegis/Ion show remaining duration, Repulsor fills toward discharge and Arc shows shots remaining. Presentation clocks freeze on pause, reset with the runtime and preserve restrained feedback with reduced motion. `energy-material.js` supplies procedural charge, muzzle, pressure and impact surfaces. Arc muzzle flashes are replayed with the combat visual state. `ion-ribbon.js` joins shared endpoint frames in one dynamic mesh, with a tapered live head between emission samples; this is presentation only. `sound-design.js` defines layered tones and seeded filtered noise. The race and device buses decode their `sample-cues.js` sets on unlock through `src/audio/sample-bank.js`; physical collisions and generated device cues have no alternate synthesis. Missing files stay silent and dev previews report errors. The device bus owns two sustained noise beds, four prioritized cue slots shared by samples/synthesis, bounded 8 ms retiring tails and a local compressor; empty/low-priority cues cannot evict attack feedback. Core enables the shared combat service from the active layout; no circuit-specific combat implementation is needed. `tools/pickup-layouts.test.mjs` discovers every production map and checks coverage, placement clearances and physical gate collection by player and rival. `src/pickups/combat.test.js` and `tools/combat-runtime.test.mjs` cover independent collection, active-weapon exclusion, shield/impulse behavior, cover, sustained trail exposure and deterministic replay.

The opt-in `src/physics/flight.js` model supplies ballistic flight, swept landings and timed recovery. Nacre's adapter retains its authored rules, identity, scenarios. Level adapters may supply pure grounded surface/force and airborne force samplers; zones, heat and events remain level-owned. Per-call surface options default to unchanged magnetic response. Optional authored jumps retain supported main-road traversal; actual transfers keep strict landing-checkpoint validation. See the [level API](docs/LEVEL_API.md#shared-local-mechanics). Local flight, surface, hazard and force rules use versioned session adapters. Shared defaults remain compatible with existing circuits.

### Time Trials and player records

Time Trial is a fixed centre-grid start from rest with 100 reserve and seed 7: unlimited laps on circuits, one descent to the supported terminal checkpoint on sprints. Countdown time is excluded. Manual boost and passive regeneration remain active; automatic road devices and their presentation are disabled. Solo trials have no rival contacts. Authored hazards remain active. Automatic failed-jump recovery retains validity and costs elapsed time; checkpoint violations or manual recovery invalidate the current lap/descent. The next circuit lap starts valid. R and Retry Time Trial start a fresh countdown with the same ship and rules. Pausing or returning to setup retains the current attempt; starting another mode replaces it.

`src/race/index.js` accepts finite `laps` for bounded events and `continuous: true` for circuit trials. Both interpolate checkpoint/finish timestamps within the fixed step. ### Shared physics and collision queries

Levels can opt into `createCollisionWorld({ track })`. Core owns one CPU world before presentation and shares it with the player and independent rival runtimes. `src/physics/collision-world.js` indexes authored triangles in a BVH and sweeps the whole oriented arcade hull with continuous translation and conservatively bounded rotation. `src/physics/hull.js` centralizes its established dimensions/projection math. Physical detection precedes landing acceptance: heading, half-width support and the current jump interval determine relatching only. Rejected borders deflect along their actual normal; solid deck/scenery hits bump into timed recovery. Recovery keeps sweeping, with six contacts per substep and deterministic impact cooldown/state. Geometry and collision rules join replay identity; world contact positions/normals reach shared sparks and Aegis feedback. Levels without a collision world retain their existing path. The eight expansion flight circuits register exact production road solids around their jumps with level-owned selection; Vesper also bakes its placed landing bough from the production GLB. The shared extractor preserves gaps and instance transforms without depending on presentation quality. Cindercoil also registers its production deck, ramp-end faces, walls, keel and large supports in a bounded vent-jump corridor; distant scenery and the environment GLB remain outside that first pass.

Every production racing descriptor receives one shared `src/physics/rapier-world.js` service (pinned Rapier 0.21.0); an optional async `createDynamics({ track, collisionWorld })` factory supplies level-specific settings. Game code owns pose and velocity. Rapier supplies scene casts and proximity queries against authored solids and the other racers; it does not integrate dynamic bodies or solve hover joints. Session stages all ten actors, advances their proposed movement over one shared 120 Hz tick, then finishes landing, recovery, feedback and race timing. Player and AI use the same controller.

Each chassis uses one convex outer envelope of its model-derived collision vertices. This preserves measured outer dimensions and silhouette while closing openings between structural pieces; gaps between wings are not rail-catching hooks. The controller uses box inertia from those bounds for its authored bump/spin response. Collider hashes, chassis identity and query rules participate in replay identity. Disabled native query proxies cache the convex geometry; direct pair queries place those proxies at trial poses, but they never enter the static broad phase or receive a native physics step. The static spatial index is built once when the level loads.

Countdown, scenario placement and recovery use the same road-skin and whole-hull clearance calculation as the first driving tick. Placement leaves collision actors inactive until their runtime is staged, so disabled rivals remain absent in practice.

`magnetic-body.js` retains handling profiles, thrust, drag, lateral grip and steering assistance 0.3. Grip exponentially damps lateral slip at the profile’s response rate, without a fixed acceleration ceiling that would weaken steering at boost speed. Bumps retain momentum and settle through that same grip. It proposes a displacement along the actual road skin, including bank, slope and tube coordinates. This avoids the sideways drift of repeatedly advancing on a flat tangent plane through an inversion. Support supplies the destination and normal; queries accept or clip the motion. Route projection in `finish()` describes the accepted pose, rather than moving a contacted ship back to its expected station. Ordinary contact exchanges road-plane motion and yaw without lifting supported racers over rails. Finite off-road support and sustained boundary straddles release adhesion, freeze course progress and recover at the departure station after 1.5 seconds; a hull that separates cleanly can drive away immediately.

Authored deck triangles retain metre-based `roadCoordinates` from their render geometry. `road-surface.js` indexes these faces by route distance: height comes from the exact top triangle and orientation interpolates shared-vertex derivatives weighted by route-space triangle area. Tiny bevel faces therefore cannot impose their steep tilt across broad flat panels; weighting is computed once when the surface index loads. Magnetic support and whole-hull clearance use that skin, with the route sampler as fallback outside collected geometry and for closed tubes. Supported actors declare adjacent deck owners and their route interval, including aligned backing within 0.35 m beneath the selected panel. Queries ignore only that already-owned skin. Other road layers, undersides, rails and airborne contacts stay solid. `magnetic-boundaries.js` supplies missing physical road edges, preserving jump gaps, authored curb coverage and closed tube interiors.

Dense, extensive static meshes are partitioned into 96 m spatial cells, retaining every original face and its metadata. Parameterized top faces additionally separate into 64 m route spans so crossings cannot share ownership. Small primitives and coarse faces stay intact. Swept enclosing bounds query the immutable scene index first; collider-to-collider casts then reuse cached native hulls. Both ordinary sweeps and contact separation avoid the convex-mesh reconstruction performed by Rapier’s shape-based scene-cast API. Conservative distance advancement then checks both translation and rotation, including support/capture rotations and turning in place. Contact events advance all racers to the same impact time; an impulse changes the remaining proposal for affected actors. Sliding, mass-weighted racer bumps and bounded separation are authored controller responses. Separation is swept against solids too. Query/contact limits clip unresolved movement rather than permitting tunnelling, and a difficult actor cannot exhaust the entire field's movement allowance.

Flight releases support at a shared tick boundary and integrates gravity, propulsion and attitude control through the same query controller. Actual receiving-deck contact, finite hull overlap and the existing landing guards determine reattachment. On the next supported tick, the controller absorbs pitch/roll spin and normal bounce, transports the existing heading onto the road normal and applies steering yaw immediately. Alignment is swept with whole-hull clearance and can still be clipped by a solid. A separate 160 ms presentation blend preserves the touchdown pose and eases visible tilt/height to the accepted road pose; it never holds back traction or steers toward the route heading. Blocked alignment shows the accepted physical pose. Both physical state and the visual blend participate in snapshots. Other contacts still produce deflection, spin and recovery. Contact feedback deduplicates impacts and shares cooldowns across ground/air transitions; shields protect reserve without cancelling momentum.

`physics/landing-zone.js` adds 150 m of receiving runout beyond each authored `landingEnd`, capped at the next takeoff and course finish. Contact acceptance and the overshoot recovery bound share that limit across sampled and physical solvers. This permits boosted overshoots to touch down on existing road without changing trajectory, geometry or recovery checkpoints. A successful transfer credits ordered checkpoints within the runout; it cannot jump across the next gap or finish. Short, sideways, underside and out-of-range misses retain recovery.

Snapshots contain game-owned actor pose, velocity, pending acceleration/support proposal and contacts alongside adapter state. Native query caches are derived and are not serialized. Restore validates the rules/geometry identity; old rigid-body snapshots are incompatible. Competitive replay includes the ordered field, handling, grid and runtime identities. Reset clears actor state; manual recovery resets only its actor. CPU/shape callers that omit dynamics retain the existing coordinate solver.

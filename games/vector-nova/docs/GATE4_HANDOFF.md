## Common preflight: one owner, one bounded dependency

The current runtime hardcodes Halcyon/orbital and separately calls physics for live play and replay. Injectable level/gameplay adapters do **not** exist yet. Worktrees alone prevent file races but do not solve conflicting core designs. **Gate 4.1 owns this small preflight before either lane depends on new integrated runtime hooks.** Gate 4.2 can develop isolated pickup logic/tests meanwhile.

1. Gate 4.1 adds a small optional session-runtime contract, defaulting to the existing magnetic simulation. Use one advance path for both live ticks and replay. Wire initialization, fresh lap/restart/scenario/recover, snapshots, version checks, rendering and disposal consistently. Include adapter-provided review scenario metadata and deterministic scenario initial state so the mechanics lane can expose parked pad/shield/impact starts without editing core or track files. Wire the rules identity into replay compatibility and session race history/best comparisons before freezing the seam; the current race records are in-memory, so no new persistence or Time Trial system is required. Preserve current Halcyon/orbital output and handling when no adapter is enabled.
2. Add a working no-op `src/pickups/halcyon/index.js` factory, enabled only for exact track ID `halcyon-viaduct-4-compact` AND the explicit feature opt-in. Passing that flag on orbital or level 3 must do nothing. Gate 4.1 writes the initial stub only; its ownership then transfers permanently to Gate 4.2.
3. Contract: a factory receives `{track, scene, ship, host, settings, emit}` and returns a deterministic vehicle advance, lifecycle reset/restore, serializable snapshot, version/rules identity, owned review scenarios/initial state, presentation update and disposal. The advance accepts `(state, input, dt)` and returns events; the no-op delegates `stepVehicle`. Specify tick order and exact method names in a shared `docs/GATE4_RUNTIME_CONTRACT.md` before handing it over. Keep transient presentation out of replay state. New options are additive, with baseline defaults. No optional import may reference a missing future level module.
4. Level 3 will supply its own adapter for airborne state, flight pose and landing/recovery; Gate 4.1 owns the core/camera/render wiring for that optional pose. Gate 4.2's adapter uses the ordinary magnetic pose, so it needs no core, camera or renderer edits. Preserve driver-visible left/right and normal camera behavior in adapter-free races.
5. Verify no-op behavior, record the contract and preflight SHA in both lane records, and make the exact preflight available to Gate 4.2. Use an isolated preflight commit when authorized by the launching session, then cherry-pick that commit only; no unrelated unfinished art. If commit authorization is absent, hand over the reviewed patch explicitly. Gate 4.2 verifies its imported base before browser integration.
6. Freeze the contract. Later needs become a written integration request with caller/behavior/test expectations, not another lane editing shared files. Do not merge half a level to obtain a mechanic hook. Do not copy core/main.js or build a parallel game entry.

This short startup dependency is deliberate. After it, each lane owns its complete implementation and can finish in either order without the other lane's feature code.

## Goals, criticism and human review

Each session uses one independent critic and a lane-local counter, initially 0/8. The level lane's early shape/jump goal ends at a human handback; after explicit shape approval, start its complete production/critique goal. The mechanics lane can run its complete scoped goal immediately after preflight, showing an early playable pair for steering without inventing a mandatory additional approval gate.

Critics inspect the actual production build themselves: real keys and short motion sequences, their own stills, close/medium/distant views, high/low quality, responsive UI and relevant failure/recovery states. They write no implementation. Record build hash, category scores, verdict, reproductions, impact, owner and acceptance condition per finding. Fix the highest-impact defects, then rerun affected checks plus needed regressions. One combined gauntlet per lane includes its art, track/gameplay, camera, VFX/UI and stability; do not multiply the eight attempts across submodules.

Stop at the first verified pass or round 8. A pass still needs every applicable rubric category at least 9/10, zero required-asset/runtime errors, no critical defects, and verified performance evidence. Split tested visible feedback from unverified audio listening; deferred AI is N/A with a reason. Missing foreground/hardware evidence is not a fabricated pass and does not justify repeatedly rerunning unchanged reviews to fill eight rounds. If only external evidence remains, record that hold and hand back the candidate. At the cap preserve actual shortcomings, finish packaging in scope and await human judgment.

Always retain the independent human gate, even if the critic passes. Human feedback caught problems the formal Gate 3 scores missed: the original roadway still felt like Halcyon, small neon highlights did not change its identity, and a mostly black sky weakened the space setting. Review the **entire world and raceway**, including ordinary stretches, not only hero landmarks. Keep the successful gaps, bold full-surface color where appropriate, distinctive boundaries and layered surroundings as lessons, not assets to duplicate everywhere.
